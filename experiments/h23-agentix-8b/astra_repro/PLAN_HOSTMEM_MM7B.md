# 计划 3:trace 最新论文场景,发现 baseline 方法的不足(host-mem 权重驻留族)

更新:2026-09-21(全文重写梳理)

## 0. 方法核心(与计划 1 共用规范表述)

三类机会(资源墙/并发墙/高延迟)+ 直接定位到代码区间与 process 类型;
四层对象、三遍漏斗、串行执行、独立验收(见 method-spine.md)。


## 方法管线(规范,2026-09-21——profile+trace 串行,多轮迭代)

每轮迭代 = 两段串行 + 决策:

1. **profile(process→FX graph 定义)**:对目标引擎/模型做 FX graph 捕获 →
   算子级闭包划分 process(unclaimed 节点=0 为闸门)→ 生成 NVTX 插桩点。
   process=代码区间的"定位性"由本段构造保证;**新引擎/新模型架构接入必须
   先跑本段**(不允许跳过 process 定义直接 trace;确不可行处逐架构声明);
2. **trace v3(三遍→perf timeline)**:P1 NVTX-only 整段 → P2 条件触发窗口 →
   P3 条件门控计数器,串行、独立验收,产出四层 perf timeline(prog/step/
   process/kernel);
3. **优化决策**:三类机会(资源墙/并发墙/高延迟)→ 发现→杠杆映射 →
   实施 → 兑现率审计;
4. **多轮迭代**:每次修复后系统已变,旧归因过期——**必须回到 ① 重新
   profile+trace**(实测教训:eager 臂归因外推到图臂两次失败);判停 =
   最高层发现余量 < 噪声带。

本方法 ≠ 仅 trace:profile 段是定位性的来源,trace 段是证据的来源,
迭代是有效性的来源,三者缺一即退化为一次性归因。

## 1. 目标(2026-09-21 校准)

**基于主机 Mem + 单卡 GPU 的多类 LM(LM/VLM/ALM)负载场景,对最新 baseline
方法的实验场景应用 profile+v3 trace,开放式普查是否还有进一步可挖掘的优化点。**
场景:多引擎权重超显存(3×7B ≈ 42GB > 24GB),host memory 进入服务路径——
ServerlessLLM / C2CServe / FlashServe / NOvASERVE / vLLM Sleep Mode 一族的设计点。

- **发现方式 = 开放普查**:四层三遍全量 trace,所有墙一并陈列(PCIe 带宽
  利用、换入粒度、wake 串行化、KV 重建、换入-计算重叠度、权重缺席期的
  调度行为、…);§3 的预注册项仅为待检假设,普查结果才是交付;
- **baseline 年限(强制)**:baseline 须为 **2025 年及之后** 的工作;
- **baseline 忠实性条款(强制)**:引擎、负载、模型、到达模式、硬件配置、
  指标**完全参照调研到的最新 baseline 论文的实验设置**,逐项注明出处;
  不是我方固定设定。不可复现项(集群规模、专有 trace 等)逐项声明替代
  与理由;自造成分仅允许出现在扩展场景。实验目的唯一:看 v3 方法能否在
  baseline 自己的场景里找到它未挖掘的新优化机会;
- **扩展场景 = agent-DAG loop**:prog 前瞻预取只在此存在,作为"进一步优化"
  的演示位,不作为对 baseline 场景的直接批评。

## 2. 场景与可运行代理

- 引擎:LM=Llama-3.1-8B(已有)+ VLM=Qwen2.5-VL-7B + ALM=Qwen2-Audio-7B(待下载);
- **baseline 机制代理(声明)**:vLLM Sleep Mode L1/L2 反应式唤醒
  (call 到达才 wake)≈ 该族系统的公共设计点;论文系统本体不可运行,
  以其公开数字作外部锚(C2CServe 切换 ~50ms 级);
- 驱动:serve_mm 扩展驻留管理器(最大驻留集 + 策略臂)。

## 3. 待检假设(预注册;地位次于 §1 的开放普查)

1. **资源墙(新 lane)**:PCIe H2D 换入带宽成为关键路径资源——权重 ~14GB
   @PCIe4.0 ≈ 秒级,与 prog 层预取窗口(工具延迟+依赖等待,0.15–2s)同量级;
2. **baseline 的内在盲区**:反应式唤醒把换入延迟完全暴露在 call 关键路径上;
   而 **DAG 早已预知下一模态**(C 的路由决策一出,下一引擎已知)——预取窗口
   未被利用是该族方法的结构性不足(它们没有 prog 层视角);
3. 修复演示:DAG 预取臂(路由决策即预唤醒)vs 反应式臂 vs LRU 驻留臂。

## 4. v3 方法扩展(修改即升版:形成 v3.1)

- class-3 硬件 lane 增加 **PCIe H2D/D2H**(Memcpy 行,与 SM/DRAM 同轴);
- prog 层事件增加 sleep/wake,与 call ready 对齐;
- 新指标:每 call 等权重时间、换入/等待重叠率(判停标尺:→1 即预取完美);
- 按执行约束条款:此扩展 = trace 定义修改 → v3.1 新指纹新谱系,
  计划 1 的 v3 产出按复用三条件裁决(阶段未变者可复用)。

## 5. 实验序列

0. **深读 baseline 实验章节**——已完成初提取,落 plan3/baseline_setup.json
   (复刻目标=ServerlessLLM OSDI'24;C2CServe 声明出界);后续深读补参数细节
   (模型集/负载 trace 与到达分布/硬件/指标/机制参数),选定复刻目标并
   落 baseline_setup.json(逐项出处);模型与负载按清单获取,替代项声明;
1. 按 setup 清单下载模型(存 /data3/docker_model/AgentSys);
1.5 **profile 段(每个新架构必做)**:OPT(post-LN)/Falcon(并行 attn+MLP)/
   Qwen2.5 三种新架构各自 FX graph 捕获 → process 划分(unclaimed=0 闸门)→
   插桩点;架构差异导致 8 类分类需逐架构适配,不允许跳过(mm 链的
   "engine×相位"部分覆盖不再作为先例);
2. Sleep Mode L1/L2 机制探路:wake 延迟、显存归还量、数值等价性;
3. serve_mm 驻留管理器 + 三臂(反应式/LRU/DAG 预取);
4. 负载两套:**主场景**=独立多模型请求流(突发到达/切换压力,复刻
   baseline 论文实验形态);**扩展场景**=双链-C 模态 loop(计划 2 资产平移),
   按证据预算定容;
5. v3.1 链:P1(prog+step+sleep/wake 事件)→ P2(条件触发含 Memcpy)→
   P3(逐引擎门控 + PCIe 计数)→ 报告(B0 时间线含换入区间);
6. 评分:makespan、逐模态 TTFT/p50、等权重时间分布、重叠率;
   三臂同批、launch_manifest、代价账本(预取的代价=提前占显存,须计入)。
