# E15 计划: 端侧多模态 agent 共驻仲裁
2026-09-24 立项 | 硬件: 2x RTX 4090(代理桌面/端侧) | 状态: 调研完成, 待设计细化

## 1. 立论: 端侧共驻的失败是灾难性的, 不是渐进的
关键证据(移动SoC刻画 arXiv 2501.14794): LLM 推理与高性能手游共跑时,
**纯GPU基线让游戏帧率掉到零**(GPU kernel 灌满提交队列, 渲染排不进去);
异构分流后 prefill 仅慢 0.5%/2.2% 且帧率保住。
=> 端侧多模态共驻的核心矛盾不是"吞吐少几个百分点", 而是**硬实时模态被软实时模态饿死**。
这与云端 serving 的资源竞争在性质上不同, 也正是我们封存的抢占择时资产重新获得意义的地方:
**当负载中存在硬实时 SLO(帧预算), 抢占时机从"省几个百分点"变成"是否可用"。**

## 2. 与已有工作的边界
- Nova(2509.21301): 单 GPU agentic VLM serving, 跨阶段并行 + inter-SM 分区 + 视觉编码器权重换出。
  **单请求内部的阶段并行**, 非多 agent 仲裁; 但其指出的"视觉编码器与LLM预分配KV争显存"是本线前提。
- EdgeCoInfer(2607.17143): 多设备拆分 + 共享视觉编码器; **跨设备**, 非单 GPU 仲裁。
- Mosaic(2605.18710): 训练侧空间复用。 移动SoC刻画(2501.14794): CPU/NPU/GPU 异构分流, 非 GPU 内仲裁。
- VL-Cache/MEDA/FastCache: 单模型内部的模态感知 KV 压缩。
**空白: 多个独立 agent、不同模态、异质 SLO 类型, 在单块端侧 GPU 上的联合仲裁。**

## 3. 核心设计: 模态决定资源画像, SLO 类型决定仲裁语义
| Agent 模态 | 资源画像 | SLO 类型 | 可让渡性 |
| 渲染/图形 | 固定帧预算, 周期性突发, SM 密集 | **硬实时**(掉帧=可见卡顿) | 不可让 |
| 视觉编码(VLM prefill) | 计算密集短突发, 激活显存峰值高 | 软时延 | 可延后 |
| LLM decode | 访存密集持续, KV 显存常驻增长 | 软时延/吞吐 | **可压缩(见§4)** |
| ASR/流式 | 低算力持续, 实时到达 | 准硬实时 | 轻度可让 |
仲裁三资源: SM 份额(greenctx/MPS 复现资产) x 显存容量(KV/激活) x 提交队列优先级。

## 4. 与 E14 方向B 的组合(关键): 可压缩内存作为仲裁旋钮
视觉 agent 的激活显存突发到来时, 传统做法只能驱逐/重算 LLM 的 KV(Nova 的换出是权重不是KV)。
有了文本主存+注意力缺页(E14 §7)后, LLM agent 可在**毫秒级坍缩为存根态(KV降至~8%)**让出显存,
压力过去后在视觉 agent 的计算窗内恢复 => **显存成为可弹性伸缩的仲裁资源, 而非硬分配**。
这条是 E14 与 E15 的天然接口, 也是两条线联合的最大卖点。

## 5. 实验设计(复用存量资产)
### 5.1 负载构造(单卡共驻, 全程并发)
渲染代理: 固定帧预算的周期性 GPU kernel(可用 CUDA graphics interop 或固定 FLOPs 的 16.7ms 周期核)
+ VLM 视觉编码(Qwen2.5-VL-3B 已在本地) + LLM decode(Qwen3-8B) + 流式 ASR(Whisper 可选)。
### 5.2 对照
A 无仲裁(全部自由共驻, 预期复现"帧率崩塌") / B 静态分区(greenctx 静态) / C 动态 resize(Bullet式)
/ D 优先级抢占(我们的三货币矩阵: 配额/挂起/CILP) / **E 本方案: SLO类型感知仲裁 + 可压缩KV让渡**
### 5.3 指标
帧预算达成率(P99 帧时间/掉帧率, 硬SLO) / VLM 端到端时延 / LLM decode tok/s 与 TTFT
/ 显存峰值与 OOM 次数 / **综合: 在保住帧率前提下的 LLM 吞吐**(主指标)
### 5.4 判定
E 相对 A(崩塌)不算功劳; 关键对照是 **E vs D(纯抢占)与 E vs B/C(纯空间分区)**:
目标 = 帧率达标率 >= 99% 且 LLM 吞吐相对最佳基线 +30% 以上。

## 6. 存量资产复用
MPK/Bullet-greenctx/POD sm_89 复现(共驻基底) / 三货币抢占矩阵与 W=0 时机定价 /
wall 口径 v3 与容量墙判据 / AutoTrace 采集 / E13 KV 手术与断点基建 / E14 存根恢复机制。

## 7. 风险
① 桌面 4090 非真端侧(Jetson/移动SoC 功耗与统一内存特性不同) -> 定位为"桌面级端侧代理", 诚实标注;
② 渲染负载需真实图形管线才有说服力(纯 compute kernel 只是代理) -> 尽量用 interop/真实渲染循环;
③ 跨进程 SM 共享受限(本仓已实证: green context 是 context 内分区, 跨进程须 MPS/MIG 或单进程多流)。
