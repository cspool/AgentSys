## 一. 三个真实论文并发机制的复现

| 机制 | 仓库 | 复现结果 | 关键适配(均为容量参数) |
|---|---|---|---|
| **MPK** (megakernel) | mirage-project/mirage@mpk | 基线 17.945 -> **4.274 ms/token, 4.20x** (论文 1.2-6.7x) | 无需适配(megakernel 96KB 恰入 99KB); 模型换 Qwen3-1.7B |
| **Bullet** (green-ctx) | zejia-lin/BulletServe | SM 分区使 **P99 TTFT 142.6->101.3ms (-29%)**; TPC 线性 1/1.97/3.93/7.33x | libsmctrl 补 CUDA13.x 偏移 0x604; TPC 表加 rtx4090=64; memfrac 0.879->0.70 |
| **POD** (SM-aware 融合) | microsoft/vattention | V1 占用率=2(硬指标) / V2 **36/36** / V3 实测 1.75 CTA/SM; figure13 完整复现(2CTA 1.209x/4CTA 1.222x/最优 1.249x, 最高 1.539x; 论文 A100 avg 33%, 本机 avg 25%) | 见下 |

**POD 的 sm_89 适配**(细节在迁移文档): 原版 80KB/CTA 在 Ada 仅 1 CTA/SM => 机制死亡;
锁 kBlockM 与 warp 数只砍 kBlockN -> 48KB/2CTA 恢复机制。HFuse 对照(smem 相加)原版 144KB>99KB
launch 被拒(实测 invalid argument), 砍至 96KB 后 PASS。4CTA 档(fp=11)需恢复 A100 线程结构
(P 2warps+D 1warp, blk_factor_d=2)并 kBlockN 减半 -> 24KB x4; split decode 有 32KB oaccum 地板
(与 kBlockN 无关, sanitizer 实证), 4CTA 仅 decode 不 split 时可达 —— **A100 亦然**(论文机制的补充认识)。

失败复现的如实记录: Bullet 服务端在持续负载下崩(共享 KV 池, 三次崩于占用 56-73%, 换 triton/限并发/
夹池均无效, 2^16 假设被证伪) —— 其 greenctx **机制**改由 libsmctrl 直接绑定实现(resize 版实测比
静态 50/50 分区快 19.3%, 复现了论文动态优于静态的主张)。

## 二. 墙的构造与口径

**口径 v3(用户定稿)**: 疑似墙 = 主轴−次高 >= 30pp(即算墙); 严格墙 = 另加主轴 >= 80%/可达峰值。
**容量墙入册**: 疑似 = 占用>=90% 或为 occupancy 绑定限制因子; 严格 = >=95% 且绑定(池类以 OOM 为铁证)。

用 POD 自身负载(非合成 kernel)构造的墙, NCU 实测:

| 相位 | 主轴 | 次高 | 判定 |
|---|---|---|---|
| TC 相(prefill 重 chunk4k) | TC/峰 93.5 | L2 20.5 | 严格 TC 墙 |
| DRAM 相(decode 重 B64/KV8k) | DRAM 96.4 | TC/峰 37.8 | 严格 DRAM 墙 |
| 全饱和(双高) | TC/峰 87 | DRAM 71 | 非墙 —— 命题对照臂 |

**L2 墙封口**: KV 压进 72MB L2 后 DRAM 归零(96.8->0.1%)但瓶颈越过 L2 直落算力(TC 73.6%, L2 仅 37%)
—— Ada 的 L2 带宽对 attention 过配, L2 吞吐墙不可构造; **L2 容量的作用是搬迁墙而非自己成墙**。
smem 带宽墙同判不可构造(FA2 系 shared 管线利用率上不去)。

容量墙实例(实测): MPK 持久 CTA 排他持有 96KBx128SM; pod2 寄存器 99.6%+smem 96%;
hfuse 96KB/CTA; KV 池 OOM(准入堵塞形态)。

## 三. 抢占货币阶梯与矩阵(全程构造性等功: K~232, duty~0.30, 偏移多重集相同)

### 货币 I: 共驻/配额(软, 生效延迟~0, 受害者零状态)
- 正交性(POD 受害者, n=3): TC 轴 ΔSTP +1.17%(34x噪声) / DRAM 轴 −0.73%(15x) —— **符号翻转+双轴剂量单调 => 资源正交性成立**, 等预算摆幅 1.9pp。
- 五机制(n=2): serial +0.03 / streams +0.70 / hfuse −0.01 / pod2 −0.29 / **pod4 +6.53%**(G_p +71%)。
- 墙态vs全饱和(wave02): **greenctx +2.07%**(双账户同向, 抢全饱和为负和 STP 0.9906) —— 计划命题证实; pod2 STP 持平仅受害者保护(容量墙门控)。
- 附发现: 空间分区型受害者上 **mask 拓扑压过相位时机**(wave12 greenctx 反向 −0.18%)。

### 货币 II: 真挂起(硬, 延迟<=1迭代, 干净停+等恢复, c≈0)
- 受害者扰动 19-29%(≈duty), 被打相位 G_v→0.55, 未打相位完好。
- 分相等权下两臂扰动几乎相等 => **干净硬抢占的时机 = 产出选择问题**(杀谁的活), 非机制干扰问题。
- 抢占者全让渡下 G_p 0.30-0.37(三货币中最高)。

### 货币 III: CILP(最快, 指令级, 独立 context 硬件时分)
六机制全表(受害者总扰动 / 被打相位存活 / G_p / ΔSTP(打墙−打饱和)):

| 机制 | 总扰动 | 被打相存活 | G_p | ΔSTP |
|---|---|---|---|---|
| serial | 10-20% | ~0.70 | 0.18 | −8.6% |
| streams | 11-19% | ~0.70 | 0.18 | −7.3% |
| hfuse | 11-18% | ~0.70 | 0.18-0.19 | −7.5% |
| pod2 | 11-17% | 0.71/0.75 | 0.16-0.18 | −4.1% |
| pod4 | 9-18% | 0.71/0.77 | 0.15-0.18 | −5.7% |
| greenctx | 8-20% | 0.72/0.74 | 0.16-0.18 | −9.9% |

- 伤害完美局限在事件相位(未打相位 G_v≈1.000); 切换税 ~1.75ms/burst 仅占 0.6%, 被时分损失淹没。
- **c(态) 首个非平坦证据**: serial 类 ≈0-1.5pp 平坦; pod2 −3.6/pod4 −5.5/greenctx −2.1pp
  —— 带 SM 内调度机构/resize 的机制在访存重相位被打断更疼(drain 方向)。

### 共驻形态对照(MPK)
独立 context STP 0.925(纯时分+7.5%切换税) / MPS+TC 轴 1.100 / MPS+DRAM 轴 1.199;
配额动态范围 1.33x 未过 1.5x 门禁 => MPK 判为空间抢占不可达(容量墙), 只剩时间片。

## 四. 统一规律(本研究的核心产出)

1. **容量墙门控择时**: 受害者被容量墙锁死(hfuse/pod2/MPK)时任何时机都无杠杆; pod4 的小 tile 解开
   容量墙后时机值 +6.5%。c 侧(容量占用)决定 W 侧(择时)的发挥空间 —— D=cxW 的实验版。
2. **货币类别决定时机语义**: 软货币=干扰调制(正交时刻正和); 干净硬货币=产出选择(打低产出相);
   CILP=时分+小状态税。**同一 greenctx 同一相位对: quota +2.07% vs CILP −9.85%, 异号**
   => 时机规则不可跨货币迁移, 联合建模(E10)为必须。
3. **D(s) 紧迫性定价**(实测拼装): s≈0 CILP(受害者 8-20%, 强制均分) / s>=1迭代 挂起(19-29%, 全让渡)
   / s>=相位周期 配额(1-4%, 可正和) / s>=工具期 驱逐 W=0 等待者(≈0, 待实测)。
   松弛买到的不只是更便宜, 是**不同的分成结构**。
4. **agent 负载的接口**(E8/E9/E9a): 阻塞因子=优先级; 工具期=W=0 受害者(零吞吐容量墙, 永远先抢,
   无速度要求); 调度器组批即制造相位(墙是决策变量非随机变量); 抢占组合管理(便宜档是贵档的保险)。

## 五. 效果量级的诚实评定

- 单货币内择时摆幅: 0.7-6.5%(软) / 4-10%(CILP, 避免打错相位的止损) —— **作为单独启发式: 不够**。
- 完整决策空间(货币x时机x受害者态)摆幅: **STP 0.975-1.18, ~20pp** —— 作为联合调度模型: 成立。
- 择时是零成本决策(同一次抢占换落点), 且到等待时间口径有排队放大(ρ=0.95 时 x20-30)。
- 大数字的路径(未测): E4 KV 驱逐货币(c=重预填, 比 CILP 税大 1-2 个量级)、E9a 程序级 p99、更高 duty。
- 本底座为最温和场景(单受害者/单抢占者/duty 0.3): 10% 是下界不是上界。

## 六. 方法学教训(踩过并修正的坑, 供后续复用)

NCU: --kernel-name 需 regex: 前缀; --cache-control 默认刷 L2(DRAM 0.42<->72.6%); --launch-skip
按进程计数会抓到预热/curand; **NCU 串行化 kernel, 对需 worker/scheduler 互通的持久 kernel 死等**
(MPK 满载 50min 零产出), 改用 nsys; NCU 不支持 MPS。
测量: solo 锚可被残留进程污染(592 vs 真值 815.76); 高 rho 下成对本地基线被污染须整段剔除;
时序须交错注入; 桶级归属被在飞流水抹平(窗口总量才可信); 迭代计价与分相等权计价可致结论反号,
须双口径并报; 挂起下相位钟按墙钟走保臂间可比。
工程: pkill -f 会自杀(三次) -> pgrep -x/按 /proc/PID/environ 的 CUDA_VISIBLE_DEVICES 隔离;
管道 rc=$? 取到 tail 的退出码 -> PIPESTATUS; uv venv 无 pip; 旧 egg 遮挡新构建(查 so 时间戳);
两卡共用信标/按进程名清理会互相污染 -> 按 GPU 分离; HFuse 单 TU 151 entry 致 ptxas 爆
(O3 >2h, 运行时不可达 TU 用 -O0 预编链入)。

## 八. 叙事勘误(2026-09-23, 用户定稿)

本报告中"正和/可正和"等表述须按以下规范重读: 抢占是机制需要、本身为负面收益的动作,
其优化只能表述为**减少或抵消负面收益**。quota 货币下的 STP>1 是共驻(空间共享)本身的收益,
抢占事件叠加其上仍为净负项; wall-aware 的作用是把不可避免的损失放在损失最小处
(wall 时刻在飞有用工作少), 而非创造收益。抢占全饱和时刻的额外恶果: 全饱和是组批拼出的
短暂成果, 打断后未必能重建(重建滞后为 serving 级待测预言, kernel 级不可见)。
