# 并发设计与墙感知调度：现阶段结论

日期：2026-09-22。硬件：RTX 4090 ×2（Ada sm_89），128 SM / 64 TPC / 1536 线程·SM /
65536 寄存器·SM / 450 W 板级上限；驱动 595.91.07（报 CUDA 13.2），CUDA 12.8，torch 2.11.0+cu128，无 MIG。

## 0. 口径声明（取代此前的"基底"）

**并发设计** = 让两个负载同时占用 GPU 的方式。它横跨六层，不止是"用哪个 API 切 SM"。
此前文档把"基底"只用于 L2/L4 那两行，是窄了；角度 1/2/3 其实是同一张表的其他行。

| 层 | 单位 | 这一层分开的是 | 跨进程能并发 | 并发设计 |
|---|---|---|---|---|
| L0 程序/调用 | call | 程序优先级、队列位置 | — | MLFQ、DAG 调度 |
| L1 引擎 | request / step | KV block、RUNNING slot | — | vLLM recompute/swap |
| L2 前端 runlist/TSG | TSG（同 ctx 的 channel 组） | 进程 / context | **不能，轮转** | MPS（合并）、MIG（隔离） |
| L3 channel / HyperQ | 物理 channel | 同 ctx 内 stream | — | stream 优先级 |
| L4 CTA 派发 | **TPC**（Ada = 2 SM） | kernel 的 CTA 落点 | — | green context、libsmctrl、CTA 融合 |
| L5 SM 内 | warp slot / 发射带宽 | 同 SM 上的 warp | — | **blockDim 几何**、warp 融合、持久 kernel、CILP/SCG |

**L2 是硬边界。** VUDA（arXiv 2605.01352, 2026）的核心前提与此一致：同 context 的 channel 共享一个
TSG，不同 context 必然互斥时间片，称 *execution isolation*，并断言现有机制无一能克服。
推论：想摆脱 MPS，正确做法不是换 SM 划分 API，而是**取消跨进程结构**——这也更贴近真实 serving
（vLLM 是单进程，抢占本就发生在同一 context 内）。

## 1. 五种并发设计：实测与结论

### 1.1 L2 —— MPS（合并 TSG）

- **实测**：单进程两条流（`none`）在两轴都不输 MPS：扰动 2.58 vs 2.59 ms（持平），抢占者 e2e
  22 vs 29 ms（快 24%）。
- **结论**：MPS **不是并发的必要条件，只是跨进程并发的必要条件**。它是合并而非隔离
  （ECRTS'25：MPS 的 subcontext *does not isolate clients in the GPU hardware scheduling pipeline*）。
- 真隔离的是 MIG（按 SysPipe 切 SMC Engine，各自 channel+runlist），4090 不支持。

### 1.2 L4 —— green context / libsmctrl（TPC 落点约束）

| | green context | libsmctrl TPC mask |
|---|---|---|
| 粒度 | 64 组 × 2 SM = 恰好 64 TPC | TPC mask，同层 |
| SM 绑定 | `%smid` 交集 **0** | 交集 **0** |
| 真并发 | 重叠 **99.9%**（单进程内无需 MPS） | **99.9%** |
| 切换代价 | 新建 2670.91 μs，**预建池切换 4.26 μs** | **1.16 μs，免预建池** |
| 可用性 | 官方文档化、PyTorch 有封装、兼容 CUDA Graph | 未文档化（靠 CUstream 结构偏移），不兼容 CUDA Graph |

- **新发现**：libsmctrl 的版本表止于 CUDA 12.7，本机驱动报 13.2 → 扫出新偏移
  **`MASK_OFF=288` → `0x604`**（可回馈上游）。
- **静态 vs 按需**：静态 96/32 分区在 4% 抢占时间占比下扣掉受害者 **10% 吞吐**（0.902）；
  按需分区全部收回（0.998–1.004）。**静态切分永远是错误配置。**

### 1.3 L5 —— blockDim 几何（零 API 的共驻律）

两侧用**完全相同**的 spin kernel 扫出的三级阶梯：

```
受害者 blockDim ≤ 224 (≤7 warp)           → 抢占者 blockDim ≥ 32
受害者 blockDim 256–480 (8–15 warp)       → 抢占者 blockDim ≥ 96
受害者 blockDim ≥ 512 (≥16 warp，实测到 1024) → 抢占者 blockDim ≥ 192
外加容量: v_block × 每SM块数 + c_block ≤ 1536
```

- 收益：共驻时合计墙钟 = 受害者单独耗时（**抢占者免费**，36 ms）；不共驻 95–110 ms。
- **不变性**（每条独立否掉一类解释）：受害者每 SM 块数 1 vs 2 → 边界图逐格一致；受害者寄存器
  16/24/45/85（理论块/SM 6→2 与 3→1）→ c_min **完全不动**；两侧同 kernel → 阶梯不变；
  剩余线程数、带宽饱和 → 无关。
- **机制未破**：已排除剩余线程、带宽、寄存器/理论占用率、块槽位（maxBlocks/SM=24）、受害者块数、
  kernel 差异；自提的 `4·c_warp > v_warp` 规则被 v=768/1024 数据推翻。疑为 CWD/MPC 未文档化的放置启发式。
- **可用规则**：抢占者 blockDim ≥ 192，受害者到 1024 都能共驻。

### 1.4 L4–L5 —— 融合 kernel（对标 POD-Attention Table 2）

抢占者总工作量固定（reps 随 blockDim 反比缩）：

| blockDim | serial | streams | cta_fused | warp_fused（最优比） |
|---|---|---|---|---|
| 256 | 75.1 | 50.4 | 49.7 | 54.8 (6/8) |
| 512 | 55.8 | **36.4** | 36.5 | 42.3 (12/16) |
| 768 | 55.3 | **36.5** | 39.2 | 36.3 (18/24) |
| 1024 | 55.4 | 55.4 ✗ | 55.4 ✗ | **36.3** (24/32) |

- 自然共驻成立时 **stream 已最优**，融合纯亏。
- 共驻失败时（1024）**streams 与 cta_fused 同时失败、数值一模一样** → 印证 POD 表里两行 GC 皆 ✗。
  （原预测"CTA 融合会反超"**被证否**：blockIdx 分工仍是不同 block，照样受容量约束。）
- **只有 warp 级融合在任何 blockDim 下恢复完全重叠**——共位是构造保证的。代价是 straggler 极敏感：
  blockDim=256 时 2/8 切分 125.7 ms，**比串行还差 67%**。

### 1.5 L4–L5 —— 持久 kernel + 任务队列（MPK 式）

2048 任务（1024 访存亲和 + 1024 算力亲和，总时长配平），**成块到达**（先全访存再全算力，
模拟 prefill/decode 相位；交错混合会让 FIFO 白拿完美配比）：

| worker/SM | fifo（亲和盲） | affinity（看在跑数取欠缺） | alternate（无状态交替） |
|---|---|---|---|
| 2 | 1.00× | 1.19× | **1.30×** |
| 4 | 1.00× | 1.33× | **1.73×** |
| 8 | 1.00× | 1.05× | **1.49×** |

- 核内混合互补亲和**确有收益，最好 1.73×**。
- **但"记录在跑任务数再抓互补类型"在所有配置下都输给无状态严格交替**（计数器读法从
  `atomicAdd(..,0)` 换成 volatile 读后结论不变）。机制：`running[sm]` 是同 SM 所有 worker
  共同观察并**同时反应**的共享信号 → 羊群/振荡；worker 越多越糟（8 worker 退化到 1.05×）。
- 这解释了 **SCG 为何把 arbiter 做进硬件、贴着每个 DPC**——软件版在 task-claim 粒度做反馈太粗太慢。

### 1.6 L5 —— CILP / SCG（无用户态接口）

- CILP 是 L2 时间片到期时"把 context 从 SM 卸下来"的执行机构；h23 早先实测 Ada 走 CILP
  （block 寿命拉长 500× 而切换税恒定，排除 drain）。
- SCG **不是抢占**，是让图形与计算在同一 SM 内按 warp 共存、从而不必切 context。
- **官方接口是 CiG**（`cuCtxCreate_v4` + `CUctxCigParam`，CUDA 12.8 头文件齐全），但唯一数据类型是
  D3D12 命令队列 → 本机 `D3D12_CIG_SUPPORTED = 0`。Linux 路径只有 VUDA（channel 重定向进 Vulkan
  的 TSG + 页表嫁接，4090 上报 +85%），**无公开代码**。
- `CU_EXEC_AFFINITY_TYPE_SM_COUNT`（green context 前身）在 4090 上 `Support = 0`。
- `CUDA_DEVICE_MAX_CONNECTIONS` 在 595 驱动上已不约束并发（16 流设 1…32，最大并发恒 16）。

## 2. 墙感知择时：三种并发设计下的对照

**负载**（`wall_preemptive`）：受害者 Triton `stream_fma`，单一 kernel 族只调算术强度，
N=120M float（480 MB ≫ 72 MB L2），BLOCK=256、GRID=768、4 路 ILP；
`inner=60` 访存墙（算力 16% / VRAM 86%，对齐真实 decode SM 13.6%/DRAM 85.9%）；
`inner=290` 全饱和（74% / 83%）；相位交替 `w,s`。
**抢占者** `fma_full` 768×256，reps=1 485 188（满卡单独约 12 ms），工作集 786 KB（L2 内）。
**控制器**：泊松到达（种子共享，各臂同一序列——固定周期会与相位周期混叠，实测出过 0/150 的假结果）；
K=300；截止期 = 0.9× 到达间隔。
**三策略**：`valve`（到达即发 + T_cool 74 ms，取自 Valve 复现）/ `wall_aware`（推迟到墙态，截止封顶）/
`random_defer`（重放 wall_aware 的推迟量但打乱顺序——同预算、不看状态，判定收益来源的唯一手段）。
**度量**：逐事件局部配对，基线 = 该迭代前同相位未命中的 8 个（免疫热漂移），两端同源绝对时钟。

| 并发设计 | 策略 | 落墙 | 墙态扰动 | 饱和扰动 | 加权每次 | 抢占 e2e |
|---|---|---|---|---|---|---|
| MPS（双进程共享 SM） | valve | 141/299 | 0.02 | 3.85 | 2.59 | 29 |
| | random_defer | 147/300 | 0.03 | 3.76 | 2.01 | 26 |
| | **wall_aware** | 297/300 | 0.00 | 1.87 | **0.10** | **18** |
| green 静态 96/32 | valve | 140/300 | 0.09 | 5.26 | 3.82 | 63 |
| | random_defer | 130/299 | 0.14 | 5.79 | 5.17 | 63 |
| | wall_aware | 294/298 | 0.04 | 3.86 | **0.20** | 63 |
| green 按需 resize | valve | 141/299 | 1.19 | 19.83 | 10.44 | 51 |
| | wall_aware | 283/284 | 1.18 | 8.67 | **1.29** | 49 |
| | wall_aware_resize | 272/278 | 12.58 | 5.33 | 13.07 | **30** |
| none（单进程两流） | valve | 21/40 | 0.56 | 3.75 | 2.58 | **22** |

扰动压缩（vs valve / vs random_defer）：MPS **26.29× / 20.40×**，green 静态 **18.99× / 25.75×**，
按需 **8.12× / 7.9×**。

**`wall_aware_resize` 的预测被证否**：墙态给抢占者 64 SM ⇒ 受害者掉到 64 SM，而我们只验过
128→96 在墙态近乎免费。净效果是用 0.7% 受害者吞吐换 39% 抢占者延迟——沿帕累托前沿移动，不是外推。

## 3. 墙论断的三次独立复现

| 复现方式 | 证据 |
|---|---|
| ① 抢占时机 | 墙态扰动 0.00–1.19 ms vs 饱和态 1.87–19.83 ms，跨三种并发设计一致 |
| ② 静态分区代价 | 让出 32 SM：访存墙相位只贵 **0.9%**（162.0 vs 160.9 ms），饱和相位贵 **19.8%**（199.8 vs 166.3 ms） |
| ③ 残余耦合机制 | green 下 SM 不相交仍有扰动：饱和相位贴 450 W 上限的 97%（435→437 W），SM 时钟掉 **74 MHz**（2682→2608），受害者直接换成时间；访存墙相位 348→351 W 有余量，时钟 2694→2700 无变化 |

**③ 的机制（板级功耗墙→降频）与 ① 的机制（SM 争用 / CILP 切换税）完全不同，却指向同一结论——
墙感知的收益不依赖单一并发设计。** 这是目前最强的一条论据。

## 4. 抢占时间占比关系与两次口径修正

> **术语定义 —— 抢占时间占比（此前称"占空比"，易与 GPU 利用率混淆）**
> `抢占时间占比 = K × burst_busy / makespan` = **卡上同时有两个负载的时间比例**。
> 它**不是** GPU 忙碌比例：受害者全程背靠背运行，GPU 几乎 100% 忙（S3 实测引擎步间空隙
> 仅占 0.4%）；也**不是**时间的划分——burst 在跑的那段里受害者同时也在跑。
> 含义：**只有在这个比例的时间里才存在任何干扰可供优化**，其余时间受害者独占。
> 这正是抢占型方案吞吐天花板被封死的原因，也是"接纳型"设计（等效 100%）成为大数值路径的原因。


| 抢占时间占比 | 扰动压缩 | valve 吞吐 | wall_aware 吞吐 | valve 损失 | wall_aware 损失 |
|---|---|---|---|---|---|
| 3.3% | 8.12× | 6.072 | 6.104 | 0.52% | 0（基准） |
| 7.9% | 8.42× | 6.013 | 6.087 | 1.42% | 0.28% |
| 14.9% | 8.60× | 5.906 | 6.066 | 3.24% | 0.62% |

- 扰动压缩在 4.5 倍抢占时间占比跨度上稳定在 **8.12–8.60×** ⇒ 它是机制属性。
- 吞吐损失斜率：valve **≈0.20**，wall_aware **≈0.04** ⇒ **同样的吞吐预算，墙感知择时能多抢占约 5 倍次数。**

**口径修正 ①：逐事件扰动 D 跨并发设计不可比。** D 相对各自局部基线算，而 green 静态的饱和相位基线
已被拖到 199.8 ms——那 20% 全程在付却不计入 D。按 D 它最优（0.20 ms），按绝对吞吐它最差（0.903）。

**口径修正 ②：D 在高抢占时间占比下被低估。** valve 的 D 从 10.44（3.3%）掉到 6.92（14.9%），因为局部基线
混进了邻近事件的扰动。拟合斜率 0.176 高于由 D 推的 0.120，差额正是这个污染。

**口径修正 ③（本次，最重要）：吞吐不是终点指标。** 抢占的吞吐代价在本负载上总共只有 3.2%，
消掉 81% 也只有 2.6%；外推 100% 抢占时间占比也才 17.6%。**用吞吐立论这条线是弱的。**
抢占从来是拿吞吐换延迟（我们自己的 Valve 复现：尾延迟 +701% → +2~4%，代价离线吞吐 79%→61%）。
终点指标必须是**等待时间**，见下一阶段计划。

## 5. 一条贯穿线与它的边界

**静态、构造性的保证胜过运行时反馈**：warp 级共位（构造保证）胜过 stream/CTA（不保证）；
固定交替配比胜过亲和反馈（羊群）；SCG 把 arbiter 做进硬件才有足够时效。

**但 `wall_aware` 本身就是运行时反馈，为何不被这条规律打掉？** 两点区分：
(a) 受害者相位是**外部可观测且慢变**的（161 ms 一个相位，不是 μs 级）；
(b) 决策者是**单一控制器**，不是 N 个 worker 同时观测同一信号一起转向（角度 3 的羊群正来自后者）。
**推论：反馈粒度必须匹配被观测量的变化速率。** 这是论文里最会被质疑的地方，须正面写。

## 6. 已知缺口（按重要性）

1. **墙的类型学不完整**：只做了 FP32 算力 + VRAM 两轴（victim6/8），TensorCore 轴（victim7）已校准
   但**在长跑对照里被丢掉了**——纯属实现惰性，而真实 prefill/decode 恰恰是 **TC 墙 ↔ 访存墙**。
   **L2 墙与 shared memory 墙一条都没做。**
2. **终点指标错位**：全部对照以吞吐/扰动为指标，**等待时间从未作为主指标测过**。
3. **抢占频率被钉死**：所有对照固定 K=300，抢占频率不是自由变量——而它正是买延迟的那个变量。
4. **全部结论建立在 Triton 合成负载上**，真实 vLLM serving 未验。
5. **blockDim 共驻律机制未破**（现象与不变性已固化）。
6. 真实抢占代价形态未量：KV recompute（可能秒级）、KV swap（PCIe bound）、批次占用
   （S3 实测抢占把短批步从 19.4% 抬到 34.5%）——这三项在 wall_aware 下都没测过。
