## 抢占机制的软硬件栈（2026-09-22 修缮：层次 / 目的 / 隔离性 / 透明性）

本节是全文的机制底座，位置提到最前是因为后面几层反复出现概念错位：把 MPS 当成资源隔离、
把 green context 当成 SM 内划分、把 channel 数当成 stream 并发上限、把 SCG 当成抢占机制。
2026-09-22 在本机（RTX 4090 / driver 595.91.07 / CUDA 12.8）逐条实测校正后固化于此。

**先声明本计划的作用点**：第 5 层的"资源墙择时抢占"主张**不发明新机制**，它改的是既有机制的
**触发时刻**。决策发生在 L0/L1（程序与引擎层，因为只有那里知道受害者处在哪个相位），
执行落在 L5（硬件 CILP）或 L4（green context 分区）。下表用来确定每次讨论改的是哪一层、
代价记在谁头上——混层就会得出"抢占开销 ≈ 0"这类只对某一层成立的结论。

### 一、六层栈（自上而下）

| 层 | 资源概念 | 调度单位 | 这一层的"抢占"是什么 | 代价货币 |
|---|---|---|---|---|
| **L0 程序 / 调用** | 程序优先级、队列位置、DAG 依赖 | call（prog 的一个节点） | 把 call 踢回队列，让位给更"贵"的程序 | 批次占用（RUNNING 少一格）+ 等待重排 |
| **L1 引擎** | KV block、RUNNING slot、batch token 预算 | request / step | vLLM 的 recompute / swap 抢占；降级出 RUNNING 集合 | 前缀重算或 KV 搬运；短批步占比↑ |
| **L2 前端 runlist / TSG** | channel 组、时间片 | **TSG**（同一 context 的一组 channel） | 时间片到期或命令耗尽 → runlist 调度器抢占在飞命令、切下一个 TSG | 全 context 上下文换出/换入 |
| **L3 channel / work queue** | 物理 channel（HyperQ 起 32 个硬件队列）、pushbuffer | channel ↔ stream | **没有真正的抢占**，只有优先级偏置；channel 抢占是 L2 换 context 的实现动作 | 无（只影响派发顺序） |
| **L4 CTA 派发（CWD→WDU→GPC）** | **TPC**（Ada = 2 SM）、CTA slot | CTA（thread block） | **没有抢占**，只有落点约束：green context / libsmctrl 规定 CTA 能去哪些 TPC | 让出的 TPC 全程不可用（静态分区时） |
| **L5 SM 内** | warp slot、寄存器堆、shared memory、发射带宽 | warp / 指令 | **CILP**（指令边界卸载）与 **WFI/CTA-drain**（等排空）——L2 换 context 的执行机构 | 切换税 c（保存/恢复 + 流水线冲刷） |

两条容易错的连接：

- **L2 的 TSG 必须整组同属一个 context**（Bakita & Anderson 原文：*all a TSG's channels must be
  from the same context*）。所以"不同进程并发"这件事在 L2 就被判死，L3/L4 再怎么切都救不回来。
- **L5 的 CILP/WFI 不是独立的抢占策略，它是 L2 时间片到期时"把 context 从 SM 上卸下来"的执行
  机构**。早期只有 WFI/drain，一个长 kernel 能把切换拖很久；CILP 才能在指令边界卸载。
  h23 早先实测 Ada 走 CILP（block 寿命拉长 500× 而切换税恒定，排除了 drain）。

### 二、机制卡片：目的 / 隔离性 / 透明性

| 机制 | 层 | 目的 | 隔离性 | 透明性 | 4090 |
|---|---|---|---|---|---|
| **MIG** | L2 | 按 SysPipe 物理切成 SMC Engine，每个 SME 独立 channel + runlist | **最强**：算力 + 显存 + 故障域全隔离，各自独立 VM Ctx | 对应用全透明（看起来就是一张小卡），需管理员配置 | ✗ |
| **MPS** | L2 | 把多进程的 stream 打进一个 server context = 一个 TSG，被 GPU 当作单个应用 | **是合并不是隔离**。`ACTIVE_THREAD_PERCENTAGE` 只是执行资源配额，不绑定具体 SM、分区可重叠；ECRTS'25：subcontext *does not isolate MPS clients in the GPU hardware scheduling pipeline* | 对应用透明（无需改码），需常驻 daemon | ✓ |
| **HyperQ / stream priority** | L3 | 消除多 stream 共享单 channel 的 False Dependency；优先级偏置派发 | 无隔离，**非抢占**（不动已在跑的 work） | 需改码（建流时指定优先级） | ✓ |
| **green context** | L4 | 限制 CTA 落点到指定 TPC 集合 | 仅**落点**隔离：L2/显存带宽/功耗全共享 | 需改码（driver API 或 `torch.cuda.green_contexts`），**且只在单进程内有效** | ✓ |
| **libsmctrl / nvtaskset** | L4 | 同上，TPC mask | 同 green context | `LD_PRELOAD` 可对未改码进程生效；但 API 未文档化、与 CUDA Graph 不兼容 | 需源码 |
| **CILP** | L5 | 指令边界卸载 context，服务 L2 轮转 | 时间隔离（整个 context 换出） | **完全透明，也完全不可控**——无任何用户态接口 | ✓（自动） |
| **WFI / CTA-drain** | L5 | 等 CTA 排空后换出 | 同上 | 同上 | ✓（自动） |
| **SCG（硬件）** | L5 | **不是抢占**：让图形与计算负载在同一 SM 内按 warp 共存，从而**不需要**切 context。MPC(scheduler+arbiter) 驻每个 DPC 旁，arbiter 找 LC 不用的 hole 再申请 CTA 插空 | 无隔离——它的目的就是共存 | 硬件自动，但**有用户态入口**（见下两行） | ✓（硬件在，入口不在） |
| **CiG（CUDA in Graphics）** | L2→L5 | SCG 的**官方用户态接口**：`cuCtxCreate_v4` + `CUctxCigParam` 把 CUDA context 挂到一个图形命令队列上同时执行 | 由图形栈定义 | 需改码；**唯一的 CIG 数据类型是 `CIG_DATA_TYPE_D3D12_COMMAND_QUEUE`** → Windows/D3D12 路径 | ✗（本机 `CU_DEVICE_ATTRIBUTE_D3D12_CIG_SUPPORTED` 查得 **0**） |
| **VUDA**（arXiv 2605.01352, 2026） | **L2/L3** | Linux 上走通 SCG 的研究路径：**channel redirection**——把 CUDA stream 的 GPFIFO/UserD/doorbell token 重定向进 Vulkan context 的 **TSG**，配合 page-table grafting | 无隔离（目的是共存） | 对应用透明，但改驱动栈；需 Vulkan | 论文在 4090 上实测 1.85×；本机无 Vulkan |
| **Exec Affinity**（`CU_EXEC_AFFINITY_TYPE_SM_COUNT`） | L4 | green context 的前身（CUDA 11.4）：context 级 SM 数上限 | 同 green context | `cuCtxCreate_v3`，需改码 | ✗（本机 `cuDeviceGetExecAffinitySupport` 查得 **0**） |
| **软件门控**（Tally / Valve / 我们的 `AGENTIX_PREEMPT_GATE`） | L0–L1 | GPU 没有中断特定 kernel 的接口，于是在**提交侧**造一个软抢占点 | 取决于门控粒度 | Tally 改写 BE kernel（API 层透明、性能不透明）；我们的门控要改引擎代码 | ✓ |
| **mega-kernel / MPK** | L4–L5 | 整模型熔成 persistent kernel，worker/scheduler SM 物理分工，抢占退化为 task 队列的软件决策（切换税 c→0） | 由 megakernel 自己定义 | 完全不透明：要重编译整个模型 | ✓（需移植） |

### 三、本机实测校正（2026-09-22）

| 旧说法 | 实测 | 正确说法 |
|---|---|---|
| green context 是"让不同 kernel 的 block 到同一颗 SM" | `smid_share.cu`：不分区时两 kernel 各占 128 SM，**128 颗全部时间上共驻**；green 分区后**共驻 0 颗** | **共驻是默认行为**，green context 是用来**禁止**共驻的 |
| green context 是 SM 内划分 | `gc_cost.cu` 粒度扫描：`minCount=1/2` 均切出 **64 组 × 2 SM**，恰为 4090 的 64 个 TPC | 粒度是 **TPC**（Ada 2 SM/TPC），与 libsmctrl 同层 |
| MPS 做进程间 channel 资源隔离 | — | MPS **合并** channel（多 client → 一个 server ctx → 一个 TSG）；做隔离的是 MIG |
| channel 数 = stream 并发上限 | `conn_probe.cu`：16 条 stream 各 4 block 自旋 30ms，`CUDA_DEVICE_MAX_CONNECTIONS` 取 1…32，**最大并发恒为 16，墙钟 30.1ms**（串行应 480ms） | driver 595 上该旋钮已不约束并发；stream 是逻辑 channel，复用有限的物理队列 |
| 跨进程并发需要 MPS，所以必须用 MPS | `gc_probe.cu`：单进程内两个 green context 的 `%globaltimer` 区间重叠 **99.9%** | 需要 MPS 的是**跨进程**这件事本身。取消跨进程结构（单进程多流/多 green ctx）后 L2 整层消失 |
| 重分区代价 ~4μs | `gc_cost.cu`：新建 green ctx **2670.91 μs**；预建池后切换 **4.26 μs**（`cuCtxSetCurrent` 0.063 + 异步 launch 4.198） | 4μs 是**切换**代价，不是创建代价。用法必须是启动时建池 |

**SCG 的接口在哪（2026-09-22 在空闲卡 GPU1 上查证，修正"无用户态接口"的说法）**：

`scg_probe.cu` 的两项查询与头文件比对表明，SCG **有**官方用户态入口，只是不在
"Linux + 消费卡 + 纯 CUDA"这条路上：

| 入口 | 存在形式 | 本机结果 |
|---|---|---|
| CiG | CUDA 12.8 头文件里接口齐全：`cuCtxCreate_v4`、`CUctxCigParam`、`CU_LIMIT_CIG_ENABLED`、`CU_LIMIT_CIG_SHMEM_FALLBACK_ENABLED`、设备属性 135 | `CU_DEVICE_ATTRIBUTE_D3D12_CIG_SUPPORTED = 0`；枚举里只有 D3D12 命令队列一种数据类型 → Windows 路径 |
| Exec Affinity | `cuCtxCreate_v3` + `CUexecAffinityParam`，CUDA 11.4 起 | `cuDeviceGetExecAffinitySupport(SM_COUNT) = 0` → 4090 不支持；消费卡上 green context 是唯一可用的 L4 接口 |
| VUDA | 研究原型：channel 重定向进 Vulkan TSG + 页表嫁接 | 本机无 Vulkan loader/ICD；论文在 4090 上报 1.85× |
| NVIGI「GPU Scheduling for AI」 | 驱动层 CUDA/D3D 相对优先级（R575/R580） | 同属 Windows/D3D 语境 |

对本计划的含义：**SCG 这条硬件路在消费卡 Linux 上够不着，但 VUDA 证明它够得着的方式是
L2/L3 的 channel 重定向——即"手工做 MPS 干的事"：把两个 context 的 channel 并进同一个 TSG。**
这与本节第一条结论一致（跨 context 并发只能在 L2 解决），也给出了一条不依赖 MPS daemon 的
跨进程共驻路径，可作为后续机制选型的候选（代价：改驱动栈，透明性好但可移植性差）。

NVIDIA 自己在 `cuda.h` 留的口子（说明 L4 解决不了 L3 的依赖，只是本机未触发）：
> Even if the green contexts have disjoint SM partitions, it is **not guaranteed** that the kernels
> launched in them will run concurrently … due to other resources (like HW connections, see
> `CUDA_DEVICE_MAX_CONNECTIONS`) that could cause a dependency.

### 四、对本计划的含义

1. **主张的作用点是"何时触发"，不是"用哪个机制"。** 因此第 5 层的消融必须固定机制、只变时机；
   跨机制比较属于机制选型（第 1 层的成本卡），两者不能混在一张表里。
2. **结论在两种机制下都成立，但物理原因不同**——这是加强而非削弱：
   - L5 共驻（MPS 或单进程多流）：受害者在墙态时 SM 空着，抢占者的 work 被吸收；
   - L4 分区（green context）：两侧 SM 不相交，残余耦合是**板级功耗墙**——饱和相位已贴到
     450 W 上限的 97%（435→437 W），抢占者进来取不到电，SM 时钟掉 74 MHz（2682→2608），
     算力受限的受害者直接换成时间；访存墙相位功耗只有 348 W 有余量，降不降频都无所谓。
3. **隔离性与代价是同一枚硬币。** green context 给了精确落点隔离，代价是静态分区全程扣住 TPC：
   让出 32 SM 后，访存墙相位只贵 0.9%（162.0 vs 160.9 ms），饱和相位贵 19.8%（199.8 vs 166.3 ms）
   ——墙论断在**分区代价**上独立复现了一次。因此 green context 必须**按需**用（4.26 μs 切换），
   静态切分在 4% 抢占占空比下被"不分区"支配。

4. **⚠️ 指标口径的自我修正（2026-09-22，R12 实测后）。** 每事件扰动 D 是相对**各自局部基线**算的，
   而不同基底的基线本身不同——静态 green 分区的饱和相位基线已被拖到 199.8 ms，那 20% 的损失全程
   都在付却不计入 D。按 D 看，静态 green 的 wall_aware 只扰动 0.20 ms（最优）；按**绝对吞吐**看，
   它是 0.903（最差）。**规则：D 的倍数只在同一基底内可比；跨基底必须用绝对吞吐。**

   绝对受害者吞吐（归一化到 MPS/valve = 1.000，同负载同到达序列 K=300）：

   | 基底 | valve | random_defer | wall_aware | wall_aware_resize | 抢占者 e2e |
   |---|---|---|---|---|---|
   | MPS / SM 共享 | 1.000 | 1.001 | **1.001** | — | 29 / 26 / **18** ms |
   | GreenCtx 静态 96/32 | 0.902 | 0.901 | 0.903 | — | 63 ms |
   | GreenCtx 按需 resize | 0.998 | 0.998 | **1.004** | 0.997 | 51 / 51 / 49 / **30** ms |

   三条读数：(a) 按需分区把静态分区的 10% 吞吐损失全部收回；(b) `wall_aware_resize`
   **不是帕累托外推，只是沿前沿移动**（初始预测被证否）——墙态给抢占者 64 SM 意味着受害者掉到
   64 SM，而我们只验过 128→96 在墙态近乎免费；换算后是用 0.7% 受害者吞吐换 39% 抢占者延迟；
   (c) 本负载上 **MPS + wall_aware 在两个轴上都赢过所有 green 配置**。

5. **系统收益 ≈ D 的压缩倍数 × 抢占占空比。** 本实验占空比仅 ~4%（63 ms / 1.5 s），故 wall_aware
   相对 valve 的绝对吞吐收益只有 **+0.6%**（1.004 vs 0.998）。内部一致性核对：resize 臂
   300 次 × 13.07 ms = 3.9 s，占 463 s 的 0.85%，与 1.004→0.997 的吞吐差吻合。
   **已补（2026-09-22，占空比扫描 R12/D06/D03，同基底同负载同 K=300，只改到达率）**：

   | 占空比 | 扰动压缩（vs valve） | 吞吐增益 | valve 吞吐 | wall_aware 吞吐 |
   |---|---|---|---|---|
   | 3.3% | 8.12× | +0.53% | 6.072 | 6.104 |
   | 7.9% | 8.42× | +1.24% | 6.013 | 6.087 |
   | 14.9% | 8.60× | +2.70% | 5.906 | 6.066 |

   **拟合：吞吐增益 = 0.176 × 占空比（过原点，R² = 0.987）**；外推 50% → +8.8%，100% → +17.6%。

   两条读数：(a) **扰动压缩倍数在 4.5 倍的占空比跨度上稳定在 8.12–8.60×——它是机制属性**；
   (b) 更干净的陈述方式是看绝对吞吐随抢占频率的走向：**valve 从 6.072 掉到 5.906（−2.7%），
   而 wall_aware 从 6.104 只掉到 6.066（−0.6%）——择时让受害者吞吐对抢占频率近乎免疫。**

   ⚠️ 测量口径补充：每事件扰动 D 在高占空比下被**低估**（valve 从 10.44 掉到 6.92 ms），
   因为抢占变密后局部基线里混进了邻近事件的扰动。高占空比区必须以绝对吞吐为准——拟合斜率
   0.176 高于由 D 推的理论斜率 0.120，差额正是这个污染。
6. **SCG 是本主张的硬件先例。** arbiter 找 hole 再插空，与我们用相位信息择时同构；差别是它在
   SM 内做、入口绑在图形栈上（CiG 只走 D3D12，Linux 要靠 VUDA 那样改驱动），我们在 L0/L1 做、可编程。写 related work 时应据此定位：不是
   "新想法"，而是把一个已在图形/计算混合场景被硬件验证的规则，搬到 LLM serving 的抢占时机上，
   并给出它成立的条件（墙要够深 + 要有共驻或分区基底）。

## 总纲与立场

抢占在机器层面**永远是负提升**——它不创造 FLOPs，只重排归属，且每种机制有自己的账单。
它的功能是**时间价值套利**：等待总量守恒（或略增），从"贵的时间"（短程序串行链、面向
用户的 LC 调用）搬到"便宜的时间"（有程序内并行 slack 的 BE、长链摊薄）。因此本计划的
核心不是"实现更多抢占"，而是回答三个问题：每种机制的开销是什么（第 1 层）；agent 程序
到底需不需要抢占、开销由谁 overlap（第 2 层，重点）；抢占与高利用率 kernel 调度的冲突
如何裁决（第 3 层，重点）。

### 根本冲突（第 3 层的哲学，贯穿全文）

高利用率技术（mega-kernel / MPK、CUDA graph、PD 打包批）与抢占是**同一根轴的两端**：
前者把工作熔成更大的不可中断单元换取利用率——**整体性能优先**；后者要求细的可中断
边界换取响应性——**服务/机制优先**。熔合度每升一级（eager kernel → graph step →
打包批内 → mega-kernel），利用率涨、抢占粒度降。任何抢占设计必须先声明自己站在这根
轴的哪个点、为谁付出多少利用率。

### 成本三分法（机制选型的决策规则）

| 家族 | 代价货币 | 成本结构 | 适用时间尺度（agent 三尺度对应） |
|---|---|---|---|
| 驱逐式（非挂起） | 状态搬运带宽 | 每事件常数：保存+恢复流量 + 全冷重建；搬运本身冲刷 L2 | tool delay（100 ms–10 s）：驱逐 **KV 驻留权**而非计算（copy engine 独立通道 + 可预测返回时刻预取） |
| 挂起式 | 容量 | 分配制资源（寄存器/smem/warp slot）持续占用 → 并发↓ → 吞吐损失 ∝ 占用份额 × 时长；缓存制照样 miss（但少付搬运那份） | prefill chunk（~ms）：时长近交叉点 t\*，且 LC decode 只需少量发射带宽 |
| 门控式 | 反应延迟 | 零搬运、零占用、零污染；代价 = 等当前驻留工作跑完（期望 ≈ 被门控单元一半时长） | decode kernel（5–50 µs）：反应延迟远小于 t\* |

交叉时长 t\* ≈ 驱逐固定成本 ÷（占用份额 × 单位时间吞吐价值），本栈粗估数百 µs 量级
——待第 1 层实测后从数据直读。

### 第四种代价：批次占用（调度换手的利用率成本，S3 实测补入）

三分法按"机制怎么让出 GPU"分类，漏了一项与机制无关、只要**换手**就要付的代价：
每次把 call 踢回队列，RUNNING 集合就短一格，而解码是显存带宽受限的——批越小，
每步的 GPU 效率越低。这项代价不表现为空转，表现为**坐不满**。

r1.5 重载、Qwen3-1.7B（KV 上限 75–80x，`max_num_seqs=16` 是唯一约束，显存不挡路）：

| 臂 | RUNNING 均值 | 每步换手（进/出） | 换手率 | batch<16 且队列非空 | 引擎步间空隙 |
|---|---|---|---|---|---|
| fcfs | 13.97 | 0.17 / 0.17 | 2.5% | 19.4% | 2.5 s（0.4%） |
| mlfq_call | 13.47 | 0.36 / 0.36 | 5.3% | 31.8% | 2.2 s |
| agentix_core | 13.63 | 0.37 / 0.37 | 5.4% | 34.5% | 2.5 s |

三条读数：

1. **抢占把短批步翻了一倍**（19.4% → 34.5%），换手率同步翻倍。这是抢占**自己制造**的
   利用率损失，不是它修复的问题。
2. **它不产生空转**：三臂引擎步间空隙合计仅 2.2–2.5 s（约 10 分钟运行的 0.4%），
   步是背靠背连着跑的。代价落在"批小"而非"GPU 闲"。
3. **8B 上这项代价被显存墙掩盖**：46,784 KV token ÷ 4,096 每请求 = 11.42 并发 < cap 16，
   三臂同被卡在同一堵墙上（短批占比 19.4/33.2/20.4%），看不出机制差异。**要量这项代价，
   必须先把 KV 墙推开**（换小模型或降 `max_model_len`），否则测到的是显存不是调度。

**对机制选型的含义**：每张机制卡片除了记"代价货币"，还要记**换手率与 RUNNING 均值**。
一个在微基准上开销很低的机制，如果在 serving 里把换手率抬高一倍，它的实际账单要算上
批次占用这一项。

### 开销由谁 overlap（第 2 层的分析骨架）

1. **受害者内部 slack**（最大）：lats 波内并行（宽 5）遮蔽单调用延迟、长链摊薄。
2. **队列**：排队制下被抢占者回到非空队列，其多等时间里 GPU 在做有用功——**等待
   维度**的系统开销 ≈ 0。这解释了实测"非排队区间三策略无差异"。但 S3 实测修正了这条的
   适用范围：队列吸收的是**等待**，吸收不了**占用**——换手期间 RUNNING 集合少一格，
   短批步从 19.4% 抬到 34.5%（见上节）。所以"系统视角开销 ≈ 0"只对等待成立，对利用率
   不成立。
3. **机制专属**：前缀缓存吃 recompute；copy engine 吃搬运；门控等待期间跑的是在飞
   窗口内别人的有用 kernel。
4. **闭环反哺**（agent 独有、唯一正吞吐通道）：LC 更早返回 → 程序更早发起下一调用 →
   到达率↑ → 批更满（论文 Fig.4；实测 core 吞吐 +4 %）。

**开启判据**：三承接方（队列 / 受害者 slack / 闭环）至少存在其一才开抢占；均不在
（空载、开环、无并行）时纯亏，正确动作是不抢。above-cap 时长与波宽运行时可测。

### 评估口径（两种场景分开评，各有冠军）

- **同质场景**（Agentix 论文目标）：全体 ptl mean/p90 + 整体吞吐。实测冠军 agentix_core
  （客户端续传，mean 20.7 vs 基线 27.6）。
- **LC/BE 混部**（GPreempt/REEF 目标）：LC SLO 达成（ttft/ptl p99）为硬约束，其上最大化
  BE 吞吐。实测冠军翻转：agentix_engine（LC ttft p99 353 ms vs core 824 ms vs 基线
  2,302 ms），BE 侧全臂持平（±1.5 %）——本负载 LC 仅占 token 量 ~6 %，LC 优先近乎免费。

## 第 3 层（重点）：抢占 × 高利用率 kernel 调度的冲突

**方法立场：先对非抢占情况做分析与 trace。** 缺口 = 同负载下三种非抢占熔合配置的
利用率-粒度曲线：
- eager（kernel 粒度可门控，host 开销大）；
- graph（step 粒度一次 launch，层门控失效——layer 臂被迫关 graph 的税）；
- PD 打包（chunked prefill 混批，kernel 内部混合，launch 级机制全部失明）。

采集：fcfs × {eager, graph, 打包配比×2} 各一次 nsys capture（无抢占），量：busy%、
step 时长 vs 批内 token 构成曲线（重 forward 堆成员时长-构成关系）、抢占粒度下界。
mega-kernel 端点无实现物，以 MPK 笔记外推并如实标注未实测。

**裁决框架**：
1. 打包批内抢占的最小单元是 **token 份额**而非请求——`agentix_budget` 把
   max_num_batched_tokens 按 LC 队列状态逐 step 动态调（利用率感知门控的连续版本）；
   策略：s_t = argmax 吞吐 s.t. step_time(s_t + d_t) ≤ LC TBT SLO。
2. 能在打包 kernel **内部**做选择性抢占的只有 CTA 级机制（prefill 行 = 独立 GEMM tile
   = 独立 CTA）——agentix_resident 的存在理由。
3. 包内缓存隔离：decode KV 热区划 L2 persisting（4090 实测 51.9 MB 可划），prefill
   限制在 normal 区；NCU 量混合 step 中 decode 行 L2 命中率有/无窗口之差。
4. 空间分区条件启用：仅当 decode 自身能填满其分区时才分，否则打包（判据 = 运行时
   busy/带宽计数，lanes 已有）。

产出：**利用率增益 vs 抢占延迟下界的权衡曲线**（三个熔合刻度 + 各机制可达点），并
据此给出"整体性能优先 vs 服务/机制优先"两种立场各自的推荐配置。

- **E5 动态并发控制器**：双向执行器（准入/门控/挂起/驱逐）+ 前馈（agent 可预测到达）

### 命题(定稿)

**前提(一等条件)**:GPU 在某资源域**超载**,新工作必须挤占在跑工作——
抢占是被迫发生的。未超载(新工作可直接并发)不在讨论范围。

**命题**:在必须抢占的前提下,
> **抢占"处于资源墙"的进程/时机(某一维饱和、其余维留有空闲),
> 比抢占"资源全接近满载"的进程/时机,对整体性能的扰动更小。**

**整体扰动的定义(此前缺失,是误解的根源之一)**:

```
D = c(受害者资源态) × W(该时刻在飞/被波及的工作量)
```

- **c**:每次抢占事件对受害者的单位时延税。取决于要保存的状态量与在飞访存
  的 drain 深度。注意:**驻留状态量 ∝ occupancy(驻留 warp),不是 ∝ SM
  throughput**——初稿把 decode 的 SM 吞吐 13.6% 当成占用率,据此断言
  "decode 是廉价区",是技术错误;访存受限核往往满占用、低 IPC,状态并不小。
- **W**:kernel 被延后 X ms,则该时刻在飞的**全部**工作都延后 X ms
  (serving 里 = batch 内全部序列)。利用率越高,被波及的 kernel/请求越多。

两项都指向同一结论:资源墙态有闲置维 → 单位时间产出的有用工作更低(W 小),
且抢占机器自身的带宽/发射槽开销可落在闲置维上(c 小);全饱和态两者皆反。

### 受害者三态(实验必须齐备;初稿只有前两种)

| 态 | 算力 | 访存管线 | 属性 |
|---|---|---|---|
| 算力墙 | 82%(峰值) | ~0% | 单墙 |
| 访存管线墙 | 1% | 488% of DRAM(= 管线峰值) | 单墙 |
| **全饱和** | 73%(峰值 89%) | 479%(峰值 98%) | **无空闲维——命题的对照臂** |

(4090 实测校准,kernel 均 ~177ms。初稿把访存态标为"DRAM 墙",实为
**L1/L2 管线墙**:reps 循环复用同一 4KB,数据驻留缓存,DRAM 从未打满。)

### 机制判定(初稿未做,且硬件表有误)

初稿硬件表写"4090 无 MIG/CILP 不可编排",歧义可读作"无 CILP";
**Ada 有 CILP,实验已证**。正确判定:

| 假说 | 该有的签名 | 实测 | 结论 |
|---|---|---|---|
| WFI(等整核结束) | 抢占者排队 ~100ms 量级 | 28ms | 排除 |
| CTA/block drain(等 block 结束) | 算力核 block 活 26.6ms → 单次切换 ≥ 此量级 | 一个 burst 内十余次切换共 1.52ms | 排除 |
| **指令级 CILP** | 亚毫秒、与 block 粒度无关 | 1.5-2.0ms/burst;短 block 的访存核**反而更贵** | **成立** |

代价来源 = 状态保存量 + 在飞访存 drain,**与 block 边界无关**。
可编排性:4090 不能直接编排 CILP 时点,但可通过**提交时机**间接择时——
这正是本层策略在消费卡上的落地方式。

### 消融实验设计(修订:补齐全饱和臂与 W 轴)

**总则**:同负载同 seed 同参数,唯一变量 = 落点;每臂 launch_manifest;
三账分开(受害者/旁观者/整体);逐事件配对必须同源绝对时钟。

- **E1 三态对照(核心,取代初稿 A1 的单墙互比)**:受害者 ∈ {算力墙,
  访存管线墙, **全饱和**} × 抢占者工作量 ∈ {1,4,12}ms + 对照。
  产出 c(态);配合各态已校准的工作率算 D=c×W。
  预言:c(全饱和) ≥ c(单墙);D(全饱和) 显著最大。
- **E2 机制复核**:同为算力核(无访存混淆),block 寿命 ∈
  {0.36, 2.8, 22, 177}ms。预言:c 与 block 寿命无关(CILP 铁证)。
- **E3 W 轴标定(新增,初稿完全缺失)**:同一受害者,变在飞宽度
  (grid 32/128/1024 → 驻留 CTA ×32),固定抢占者。
  预言:D ∝ W 线性;斜率即"每单位在飞工作的扰动"。
- **E4 serving 域(原 A1/A2 升级)**:pt_phase_waves + 等量 KV 驱逐注入,
  落点 ∈ {uniform, 墙态(prefill 波), 全饱和态};三账 + batch 宽度记录,
  直接给出 serving 里的 D 分解。
- **E5 反相上限**:最好与最坏落点之差 = 该策略可捕获红利的上界。

**已废止**:初稿 A1-A4 的"相位门 decode/prefill"四臂——它们只是单墙互比,
不构成本命题的检验;其中 A3(机制家族)保留,并入 E4 的驱逐货币对照。

### A0'/初验结果(2026-09-21,离线编排微基准,v1-v5)

**方法**:受害者=Triton 长核(内部循环,DRAM 墙 464ms / SM 墙 236ms,占用同满,

**结论**:
1. **证否(context 深度)**:单小竞争者的硬件级抢占在 4090 上对两类墙均
   ≈0 成本(中位 ±0.1ms,p90 ≤0.4ms/次)——落点策略在此深度无关紧要;
   DRAM 墙受害者 SM 仅 5%,小核可直接并发,CILP 或未发生或 O(100us) 级不可见;
2. **证实方向(引擎深度)**:A0 serving 回归(边界膨胀 +21%→+42% 随 DRAM

3. **定律适用域**:切换货币量级 ≳ 相位预算的机制(KV 驱逐/批重组/权重换入),
   不含 us 级 CILP。**权重换入(GB 级)是最大应用场景 → 与计划 3 汇合**:
   换入落点选 SM 墙相、避开 DRAM 墙相,预取窗口选择新增墙维度。

**下一步(在域内做等量对照)**:A1'(引擎级等量注入)——高优先级微请求
在座位打满时强制 KV 驱逐,同 K 同负载,落点策略 {正常间隔 | 互补(SM 墙/
prefill 相)| 反相(DRAM 墙/storm 相)},量基负载三账;这才是用户消融点
(等量硬件级抢占、只变落点)在其适用域内的正规检验。

**申报限制**:单小竞争者;未测重状态竞争者/多 context;频率未锁;MPS 关。

### 受益场景消融矩阵(2026-09-21 细化;前提条件=超载,v4/v5 教训入册)

**前提(一等条件)**:优化点只作用于**必须发生的抢占**——GPU 在某资源域
超载,新工作必须挤占在跑工作。未超载(可直接并发)的扰动无收益可言,
v4/v5 即因此测在无效区(教训:消融先证超载,再谈落点)。
超载分域:SM 槽位域 / 带宽域 / L2 容量域 / 显存容量域(计划 3)。

| # | 超载域 | 抢占者(货币) | 受害者相位轴 | 等量控制 | 落点臂 | 判据 |
|---|---|---|---|---|---|---|
| S1 | SM 槽位 | 全卡满占用计算 burst(强制 CILP) | DRAM 墙 / SM 墙 / L2 驻留长核 | K 次定时 burst,busy_ms 自报 | 同 K 落不同墙相 | 每次膨胀−burst 自身,墙间差 |
| S2 | 带宽+L2 | 1GB pinned H2D(copy engine;权重换入代理) | L2 驻留 / 流式 | K 次拷贝,copy_ms 自报 | 同上 | 同上;L2 受害者预言重伤 |
| S3 | 座位(引擎级) | 高优先级微请求强制 KV 驱逐 | mixed 的 prefill/decode/storm 相 | 注入数 K 固定,座位满验证 | uniform / SM 墙相(prefill)/ DRAM 墙相(storm) | 基负载三账(受害者/旁观者/整体) |

**预注册预言汇总**:S2 L2 受害者每拷贝膨胀 ≫ 流式;S1 墙间差显现(若仍≈0,
则 CILP 在 4090 即便超载也便宜,结论上移到 S3-S5 的大货币域);S3 storm 相
注入的旁观者账最差(A0 已示方向);S4 decode-storm 窗换入使在跑引擎步时
显著膨胀,prefill 窗换入近零(计划 3 预取器的落点规则即源于此)。

### 长程端到端负载设计(2026-09-21,供 S1'/S3 深入)

短跑(45-90s,K≈24)只能给方向;定量与统计力靠三级长负载:

**L1 微基准长跑**:victim4 相序改为种子随机(相位占比可控),时长 20-30 min,
K=200-300;臂序 ABAB 交错抵消热漂移;nvidia-smi dmon 记录 SM/内存时钟入
manifest(长跑的频率漂移是一等混淆)。

**L2 serving 相位波负载(pt_phase_waves)**:用到达模式**构造交替墙相**——
每 T_w=45s 一波 B=6 个大 prompt 程序(prefill 波,SM 墙,持续 ~10-15s),
波间只剩存量 decode(DRAM/发射相);总时长 10-30 min。这给 S3 的落点策略

**L3 多引擎长共驻**(mm 资产):三引擎错相长跑 20 min,S5 准入门控的竞技场。

### L1 长跑结论(2026-09-21,K=200,20min/臂,噪声带 ±32ms)

**定律确认(4.5×)**:同负载(dram:sm=2:1 交替相)同 K=200 次强制硬件抢占
(全卡计算 burst,SM 货币),仅变落点:
- 落 DRAM 墙相(受害者 SM 5% → 侵入者的 SM 空闲窗):**+7.6ms/次**(总 +1.5s);
- 落 SM 墙相(算力硬碰):+31.4ms/次;随机:+33.9ms/次(总 +6.8s)。

**命名勘误(重要)**:互补窗 = **侵入者货币的空闲维**,不是"受害者贵相的补"。
S1' 短跑的 comp/adv 标签定反了(把 sm 相当互补窗);短跑 v1 的相反排序为
小 K 噪声,以长跑为准。定律的完整形式:
> 抢占者带着自己的资源货币;落点应选受害者在该货币维上**留有空闲**的墙相。
> SM 饥饿的抢占者 → 落 DRAM 墙相;带宽/L2 饥饿的换入 → 落 SM 墙相
> (S2' 显示分配路径相不敏感,先走预留池)。

**残余问题(下轮修)**:burst 排程(200×6s=1200s)超出受害者 makespan
(~970s),尾部 ~39 burst 打空(adv 的 39 个"强发"即是);重跑需排程 ≤ span
并按有效命中数归一;ctrl_long 排在臂后,热态偏保守(不改变结论方向)。

**下一步**:S3 serving 真域(pt_phase_waves + 等量 KV 驱逐注入,落点按
"驱逐货币=带宽/发射 → 互补窗=prefill 波(SM 墙,带宽有余)"的正确定义)。

### L2 干净结论(2026-09-21):微基准域**证否**,并推翻 L1/v6

修复三处(排程压进时长、打空剔除、中性命名)后,K=200/20min/臂:

| 臂 | 命中落点 | 命中数 | 命中 iter 总超出 | makespan Δ |
|---|---|---|---|---|
| uniform | dram 123 + sm 65 | 188 | 3.01s | +0.2s |
| sm_only | **sm 197** / dram 2 | 199 | 3.14s | +0.5s |
| dram_only | **dram 194** / sm 2 | 196 | 3.20s | +1.8s |

1. **落点控制机制有效**(命中纯度 97-99%),但**扰动量三臂无差异**
   (3.0-3.2s,差<5%),且 ≈ burst 自身工时(200×15ms=3s)——**无额外放大**;
2. makespan 的 1.6s 差是**热漂移**:非命中 iter 的中位随臂序单调变化
   (195.0/195.1/195.3 vs ctrl 195.8),ctrl_hot 崩溃未能夹逼;
3. **推翻 L1 与 v6 的正向结论**:二者均用跨进程相对时钟配对
   (victim 与 disturber 各自 t0,JIT/校准耗时不同 → 配对错位);
   本次用"时长分布归属法"(不依赖跨进程时钟)复核,错位被证实。

**方法教训(入册)**:跨进程事件配对必须用同一绝对时钟(time.time()/
CLOCK_MONOTONIC 同源),相对 t0 不可比;宁可用不依赖对齐的分布法交叉验证。

**域结论**:4090 上以"满占用计算 burst"为抢占者时,切换成本被 15ms 的
burst 工时淹没(≈0-1ms 量级),落点无肉。**用户假设要成立,需要切换货币
本身显著的机制**:S2' 已示分配+拷贝 10-14ms/次、KV 驱逐(MB 级重算)、
权重换入(GB 级)。**验证转向 S3(serving KV 驱逐)与 S4(权重换入)**,
微基准域停止追加。


### 命题校准与机制判定(2026-09-21,用户澄清)

**校准**:此前 L2/D2 的两个臂(dram 相、sm 相)**都是"单墙"**(一维饱和、
另一维空闲),从未测过"资源全接近满载"。用户命题的正确形式是:

> **抢占处于资源墙的进程/时机,比抢占"资源全接近满载"的进程/时机,
> 对整体性能的扰动更小。**

依据的物理直觉:抢占机器(CILP 状态保存/恢复)自身要消耗带宽与发射槽;
当受害者留有空闲维时,这些开销落在空闲维上;全饱和时它与受害者正面争用。

**受害者三态(4090 实测校准,kernel 均 ~177ms)**:
| 态 | 算力 | 访存管线 | 说明 |
|---|---|---|---|
| 算力墙(sm) | 82%(峰值) | ~0% | 寄存器 FMA 链 |
| 访存墙(dram) | 1% | 488% of DRAM(= 管线峰值) | 缓存驻留流式;**原"DRAM 墙"标签纠正为 L1/L2 管线墙** |
| **全饱和(balanced, inner=50)** | 73%(峰值的 89%) | 479%(峰值的 98%) | 双高,无空闲维 |

**机制判定(从 L2 数据直接排除)**:
| 假说 | 预测 | 实测 | 结论 |
|---|---|---|---|
| WFI(等整核结束) | burst 排队 ~100ms 量级 | burst 28ms | **排除** |
| CTA/block drain(等 block 结束) | sm 核 block 活 26.6ms → 单次切换 ≥ 该量级 | 整个 burst 期间十余次切换共 1.52ms | **排除** |
| **指令级 CILP** | 亚毫秒、与 block 粒度无关 | 1.5-2.0ms/burst,且短 block 的访存核**更贵** | **成立** |
成本来源:状态保存量 + 在飞访存 drain,**不是** block 边界。
E2(block 寿命 0.36/2.8/22/177ms 扫描,算力核无访存混淆)将独立复核该判定。

### 墙型口径 v3 与容量墙(2026-09-23, 用户定稿)

**双级判据(吞吐墙)**——各轴均为利用率百分数, TC 轴以可达峰值 49% 归一:

| 级 | 判据 | 语义 |
|---|---|---|
| **疑似 wall(即算 wall)** | 主轴 − 次高轴 ≥ **30 pp** | 某资源明显高于其他 |
| **严格 wall** | 上条 **且** 主轴 ≥ 80%(或达该轴可达峰值) | 主轴自身接近满载 |

**容量墙(新增墙类)**——存量占用而非流量, 不在吞吐计数器里, 用 occupancy 限制因子与池占用判:

| 级 | 判据 |
|---|---|
| 疑似容量 wall | 占用 ≥ 90%, 或该容量是 occupancy 的绑定限制因子 |
| 严格容量 wall | 占用 ≥ 95% 且为绑定限制因子; 池类(KV/显存)以准入失败/OOM 为铁证 |

吞吐墙调制 D=c×W 的 **W**(在飞有用工作), 容量墙调制 **c**(抢占需保存/驱逐的状态量)。
两类墙对抢占的含义不同: 吞吐墙 → 挑正交时机(空间配额有效, 已证 ±1.9pp);
容量墙 → **挑机制**(空间配额失效, MPK 实证 8→64 TPC 仅 1.5×; 只剩时间片/驱逐类)。

**存量数据按 v3 重判**:

**新增实验臂(并入 E 系列)**:

- **E6 容量墙×机制选择**: 受害者 ∈ {吞吐墙(POD 方波), 容量墙(MPK/pod4)} × 抢占机制 ∈
  {空间配额(TPC mask), 时间片(独立 context), 驱逐类}。预言: 吞吐墙下空间配额+择时最优;
  容量墙下空间配额失效(已有 MPK 半证), 时间片成为唯一杠杆。判定规则产出: 先测受害者
  容量占用与绑定限制因子, 决定抢占机制选型。
- **E7 L2 驻留脆性曲线(隐式抢占)**: 受害者 KV 压进 72MB L2(33/67MB 两档), 注入流量递增的
  DRAM 型共跑者, 测 L2 墙被搬回 DRAM 墙的阈值流量与受害者时延曲线。
  已有先导证据: NCU 刷 L2 使同负载 DRAM 0.42%→72.6%。命题: 对 L2 驻留型受害者,
  **共跑者的存在本身即隐式抢占**, 无需显式事件——这是现有全部格子未覆盖的抢占形态。

### E8 wall-preemptive 融入调度(2026-09-23, 讨论定稿)

**原则**: wall-aware 不决定"是否抢"(SLO 所有权留在调度器), 只提供三个从属杠杆:
1. **时机**: slack-bounded deferral —— L_i = deadline − 生效时延 − 服务估计;
   窗内等正交相位, L_i 到即强制开火 → p99 构造性封顶; LC 类 δ=0。
2. **对象**: 无松弛时挑处于墙态的受害者下手(零延迟的 wall-aware; 符号翻转数据即其证明)。
3. **机制**: 按受害者墙类选机制 —— 吞吐墙→空间配额+择时; 容量墙→时间片/驱逐(空间配额失效, MPK 实证)。

**结构性事实**: (a) serving 里调度器组批即制造相位, wall-aware 应嵌入组批器, 预测误差为零;
(b) 超载前提(ρ→1)是排队放大器, 等待 ∝ 1/(1−ρ): ΔSTP 1.5% 在 ρ=0.95 折算等待降 ~20-30%
—— "小吞吐增益×重载放大=大等待收益", 与第 5 层前提自洽。

**边界(反身性)**: 好的混合批调度本身反墙(POD 即抹平 P/D 墙); 收益在残余相位结构:
突发到达、chunk 边界、长上下文批内漂移(MPK +21%/次实测)、KV 驱逐潮。补层而非替代。

**实验**: Bullet 或 sarathi-lean; 泊松到达+超载, LC/BE 混合; 三臂 {立即, slack内延迟, +墙态选受害者};
指标 {平均等待, p50/p99 TTFT/TBT, SLO 达成率, goodput}; 扫松弛预算出 δ-vs-排队收益曲线。
预言: p50 显著改善, p99 不劣化(构造保证), 收益随 ρ 放大。

### E9 墙轨迹调度: wall 融入主调度器建模(2026-09-23, 讨论定稿; 面向 agent 负载, 充实 S4)

**建模升维**: GPU 状态从容量标量升为资源向量 x(t)=[吞吐轴|容量轴]; 每个可调度动作带签名 σ(a)
(prefill=TC, decode=DRAM, 驱逐=DRAM/PCIe, resize≈free — 均已实测); 抢占降格为带签名的普通动作,
放置规则统一为 σ(a)⊥x(t)(符号翻转实验即其证明)。调度器规划墙轨迹: 该抹平抹平(混合批),
该制造制造(把积压 TC 型事件排进故意偏 DRAM 的 iteration)。墙是决策变量, 非随机变量。

**agent 负载的三个独有前提**:
1. 阶段签名白盒: DAG 已知累计上下文、同阶段历史可估解码长 → 每程序=签名序列+工具期空洞;
2. **工具期=零吞吐容量墙**: KV 占池但 W=0、c 最小, 开窗时刻精确已知 → 最便宜的驱逐/抢占窗,
   请求级调度不存在此物;
3. DAG 关键路径给出程序级松弛: 非关键路径 call 的延迟/被抢近乎免费; fan-out 风暴可预知,
   反向排入 DRAM 型事件。

**边界**: 解码长尾打偏预测 → 两时间尺度(iteration 贪心匹配兜底+程序级规划摊销), 预测失败
退化为 E8 区间授权; 稳态抹平负载下收益→0(自洽)。

**验证**: 先 agent trace 离线回放仿真(不占卡), 三臂 {容量标量, +E8区间授权, +墙轨迹建模};
指标=程序级 p50/p99 端到端、goodput、SLO 达成。预言: 工具期驱逐胜 LRU; 收益随 fan-out/突发度增;
稳态负载退化为零。仿真胜出再上 Bullet/sarathi-lean 实机(即 S4)。

### E9a 多 agent 抢占需求结构(2026-09-23, 用户定稿的 W 原理 + 讨论)

**W 原理(用户表述)**: 必然发生的快速抢占, 落在墙态波及更少, 落在全饱和波及更多。
前提是场景需要一定比例的抢占(软流→排队, 硬流→挂起重分配, 硬快速→CILP 类)。

**agent 语义映射**:
- 优先级从 DAG 算出: 阻塞因子(下游被 gate 的任务数)=优先级; 决策/编排 agent 高阻塞因子 → δ≈0 硬快速通道。
- 等 tool_use/等兄弟结果的 agent: GPU 侧零算力零带宽, 只持 KV 容量 = **W=0 受害者**(波及在飞工作为零)。
  永远第一顺位被抢, 无速度要求; 唯一动作是 KV 驱逐(签名=PCIe/DRAM 型), 驱逐本身应排进算力墙 iteration。
- 统一评分: 受害者代价 = c(态) x W_eff, W_eff = 在飞工作 x 下游阻塞因子; 决策中 agent 只当触发方不当受害者。

**比例结构假设(可证伪)**: 多 agent 的抢占需求绝大多数松弛充足(等待态驱逐+可预知 fan-out);
δ≈0 薄流仅出现在"决策 agent 到达 x GPU 满载 x 无 W=0 受害者"三重条件下。
该比例可从 agentix trace 离线测量(E9 第一子实验, 不占卡): 每次抢占需求的松弛分布、
fan-out 时刻的 GPU 态分布、W=0 受害者的可用率。若薄流占比高则 wall-aware 收益空间受压 —— 如实报。

### E10 联合模型: 抢占货币 x 墙时机 x 调度(2026-09-23, 讨论定稿)

**统一对象**: 每货币 = (生效延迟 ℓ, 机制税 c, D-剖面)。四货币的 D 依赖墙时机的**方式**各不同:
配额=干扰调制型 / 挂起=产出选择型 / CILP=状态税型(c 随在飞状态量) / 驱逐=W 选择型(W=0 者 D≈0)。
=> 不存在跨货币通用的 wall-aware 规则, 联合建模是必要条件的候选。

**紧迫性定价曲线 D(s)**: 松弛 s 决定可行菜单(ℓ<=s), D(s) 单调降:
s≈0 只剩 CILP 付 c(态); s>=几ms 挂起选低价值相位; s>=相位周期 配额+正交择时(可正和);
s>=工具期预测 驱逐 W=0 等待者(≈免费)。各台阶均有实测点(1-4% / 19-29% / CILP在测 / 0)。

**抢占组合管理**: 便宜档提前消费(低峰驱逐等待者)压低贵档发生率 —— 便宜抢占是贵抢占的保险, 库存问题。

**押注的可证伪预言(裁决=进行中的 CILP 矩阵)**: CILP 的状态税由在飞访存 drain 主导(已有"访存核切换更贵"线索)
=> CILP 应避开 DRAM 墙相, 与配额货币的偏好**相反**; 同一 wave02 相位对下, quota(greenctx +2.07%) 与
CILP 的 ΔSTP 若异号 => 时机规则不可跨货币迁移, 联合建模从有益升格为必须; 同号则退化为每货币标量, 如实接受。

**待参数化**: c(态) 表(CILP a100/a000 之差) / ℓ 分布 / E9a 需求比例 / 并发抢占交互项(暂以串行化回避)。

### E11 agent 并发制造: 流式增量消费 vs 阻塞全量消费(2026-09-23, 用户提出)

**现象**: 阻塞语义下可调度池=未等待的 agent 数; 工具/依赖等待常长于单次推理且相关塌陷(join 点),
GPU 组合数不足。即 W=0 态占比高且同步化 —— 抢占只能瓜分既有并发, 本计划研究**制造并发**。

**两模式**: A=等全量→一次性注意力找关键(现状); B=流式部分读取(资源aware定读取多少token)→
增量判断是否继续工具→边等边完成自身任务。

**预测对比**: 利用率 A=空窗+完成时刻 TC 尖峰锯齿 / B=微工作填谷抹平;
推理长度 A=全量 prefill+长 KV / B=+judge 税 −早停省的无关 prefill(工具输出越长越噪 B 越省);
效果 A=名义上限但 lost-in-middle / B=风险在关键信息晚到。

**对调度的供给(核心联结)**: B 的微工作签名可控(分块 prefill=TC 型, judge=DRAM 型)、松弛极大
—— 墙轨迹调度(E9)的理想填充物; 与 W=0 抢占互补(未填的等待仍是免费受害者)。
块大小与注入时机 = token 粒度的墙感知准入。

**可证伪预言**: H1 利用率增益 ∝ 等待占比 x (1−池补位率), 池深时归零;
H2 净长度在长噪工具输出时 B 短、短工具时 B 长; H3 效果随关键信息位置翻转;
H4 B 的填谷供给提升 wall-p 调度可达 STP。

**分期(GPU0 only)**: P1 trace 刻画等待结构/池塌陷时间线(离线); P2 DAG 回放仿真 A vs B
(利用率/makespan/token 分解); P3 真核最小实现(pod_wave 式 agent 程序 x N, 工具以流速率注入,
B 的早停规则+分块注入, 量利用率与长度; 质量代理=关键信息位置敏感性); P4 并入 E9 调度器量 H4。

## 主线决策(2026-09-23, 用户定夺): 抢占择时研究停线, 转向调度级资源压榨

**停线理由(用户+数据)**: wall-p 本质是抢占内择时, 扰动上限 = duty x 单位效应, 被抢占时段本身框死
(实测软 0.7-6.5% / CILP 止损 4-10%); CILP 是调度系统靠编排+软抢占极力回避的(回避理由已测明:
打产出相负和), 研究被回避者的最优时机, 创新难凸显。W=0 场景的 30%+ 恰证明大数字来自
调度级对象选择而非时机 —— 时机研究的终点指向调度研究。

**停止项**: E1-E5 剩余(E2 block寿命复核/E3 W轴)、CILP 补充剂量点、五机制 dram 轴、时机类新矩阵。
**降格项**: E4 不做时机矩阵, 仅保留 KV 驱逐/恢复成本标定(作为 agent KV 管理的模型参数)。

**保留资产(转入新主线的参数与规则, 非沉没成本)**:
1. 容量墙分类+门控规律 -> 调度器机制选型规则(容量墙受害者跳过空间抢占);
2. 货币阶梯 D(s) 定价表(quota 1-4%/挂起 19-29%/CILP 8-20%, 分成结构各异) -> 调度成本模型;
3. W=0 原理 + 30% 场景实证(受害者 +53%, vs 最差 +80%) -> 新主线首个结果;
4. 三复现底座(MPK/Bullet/POD-sm89) + wp3 harness -> E11 P3 直接复用;
5. 跨货币符号反转(quota +2.07% vs CILP -9.9%) -> 系统若做任何抢占, 规则不可跨货币迁移(负结果入册)。

**新主线**: E11(流式增量消费, 制造并发压榨等待期) 为主; E9(墙轨迹 = 资源管理而非抢占择时) 为辅;
E9a trace 刻画先行(离线, 决定 E11 收益上界)。叙事翻转: 从"抢占什么时候发生"到
"等待期为什么要空着" —— 抢占研究证明了等待期是免费窗口, E11 直接把它填满。

### 收益原因定稿与叙事规范(2026-09-23, 用户定稿)

**收益原因(精确表述)**: wall-aware 抢占的收益来自——
1. 抢占 wall 时刻影响更少的进程: wall 态本身在浪费资源(单维饱和、余维空闲), 该时刻在飞的
   有用工作少, 被波及者少;
2. 抢占全饱和时刻影响更多进程: 让它们全部增加等待时间, **且全饱和态被打断后, 下一次未必能
   重新达到全饱和** —— 饱和是组批与在飞流水拼装出的短暂成果, 破坏它有重建滞后成本。
   (重建滞后在 kernel 级 harness 中不可见——kernel 恢复是即时的; 它是 serving 级现象:
   批重填/流水重灌需要时间。列为待测预言, 属 E9 范畴。)

**叙事规范(硬规则, 全部文档与论文遵守)**:
- 抢占是机制需要, **本身就是负面收益**的动作。禁止表述为"抢占带来收益/正和"。
- 抢占的一切优化只有一种合法表述: **减少或抵消其负面收益**。
  wall-aware = 把不可避免的损失放在损失最小的地方; W=0 受害者 = 损失被完全抵消(杀的是不存在的产出);
  D(s) 菜单 = 用松弛买更小的损失。
- 此前文档中 quota 货币的"正和/STP>1"表述须重读为: 那是**共驻本身**的收益(空间共享),
  不是抢占的收益; 抢占事件在其上仍是净负项, 择时只是让负项更小。

### 择时上限低的最终机制解释(2026-09-23, 用户点破+数据确认)

**持续 busy 下, 抢占落在墙时刻与全饱和时刻的扰动相近** —— 实测: 挂起分相等权损伤 0.765 vs 0.756(差1pp);
CILP 被打相存活 0.70 vs 0.70; 软货币 0-2%。
**原因: wall != 低产出**。"墙有空闲维 -> W 小 -> 抢它便宜"的直觉把资源偏斜误当产出低:
硬抢占代价 = 时长 x 该时刻产出速率, 而 DRAM 墙时刻的受害者满产出(其迭代速率甚至高 2.6x),
在飞序列数也不更少(64 vs 65)。空闲维只有软货币(不停受害者、挤进空闲维)能利用, 故其红利天然薄。
**统一公式: 择时可避免损失 ∝ 候选时刻间的产出价值差**。
持续 busy: 差≈0 -> 效应 0-2%; 产出相 vs W=0 空闲: 差=满产出 -> +54.5%。
推论: 收编后组件的决策序(W=0 受害者优先, 货币内择时垫底)即按产出差大小排序。

### E12 产出率感知抢占(2026-09-23, 用户改名定稿; wall-p 的正名)

**定义**: 抢占放置的判据从资源形状(wall)改为**该时刻的产出率**(tok/s)。wall 只是产出率的
不可靠代理(持续 busy 下 wall!=低产出, 已证); W=0 是产出率=0 的极端。
**实践优势**: 产出率是调度器免费可观测的(自己在数 token), 无需 NCU/画像。

**负载构造(真实时刻, 均 GPU-busy)**: POD 真核方波 —— 全饱和混合批(38.6k tok/s) <->
长尾排空相(仅剩单条 32k 上下文 straggler decode, 6.2k tok/s, DRAM 满扫)。对比度 6.2x。
排空相对应 serving 的 join 前 drain / 到达间隙, 非人造。
另测: 小批 decode(B_d=4)仅 1.47x 对比 —— **批宽缩小不必然产出率低**(迭代变快补偿), 附带发现。

**对照(进行中)**: 真挂起等功三臂 —— 抢低产出时刻 / 相位盲 / 抢高产出时刻。
公式预测: ΔG_v(token) ≈ duty x (r_H − r_L)/r_mean ≈ 0.4 x 32.4k/22.4k ≈ 58pp 量级(感知 vs 反向)。

**收窄史(全线三步, 均数据驱动)**: wall(资源形状) → 容量/货币结构 → **产出率**。
最终决策序: 产出率=0(W=0) 受害者 > 低产出率时刻 > 容量占用选机制 > 货币选择 > (软货币内正交择时)。

### E12 判决结果(2026-09-23): 产出率感知成立且公式定量命中

感知(抢低产出) STP 1.325 / 盲 1.080 / 反向 0.832 —— 感知 vs 反向 **+59.2%**, vs 盲 +22.7%;
受害者 token 感知 vs 反向 +156.8%。两相位均 GPU 满忙。
**公式验证: 预测 ΔG_v = duty x Δr/r_mean = 56.4pp, 实测 52.8pp(偏差6%)**。
统一公式三实测点: 对比≈1x->0-2% / 6.2x(均busy)->+59% / ∞(W=0)->+82%。
定稿: 择时可避免损失 ∝ 时刻间产出率差; 与 busy 与否、资源形状无关。产出率感知抢占为
机制库组件的正名与最终形态, 判据免费可观测(token 计数)。

### E11-KV: 提前接管输入开出的 KV 管理新机制(2026-09-23, 用户提出+讨论定稿)

现有线(InferCept/LAMPS换出, Continuum TTL, Autellix回合末驱逐, KVFlow)共同前提: 等待中 agent 的
KV 是**静态抵押品**。"提前接管输入"打破此前提, 派生四机制:
1. **工地/抵押二择**: 边流边长的 KV 与换出互斥 -> 按 预测空隙x流速xGPU空闲x下游松弛 选
   冻结换出 或 保留施工(新决策, 现有工作只有前者);
2. **KV 预制**: KV 构建与 agent 激活解耦, GPU 空闲期提前制造未来 call 的上下文 KV
   (prefix cache 的推广: 从复用到预造; 即 E9 的签名可控填谷料);
3. **流式共享前缀**: fan-out 兄弟共读上游输出 -> 边流边建一份共享 KV, N 下游同挂
   (RadixAttention 仅缓存完成后前缀; FlashAgents 有 agent 间流式但无共享流式前缀);
4. **文本<->KV 容量定价准入**: Qwen3-1.7B 每 token KV=112KB vs 文本~4B(3万倍) ->
   何时文本转 KV 是容量调度决策: 池紧滞留 host RAM, 池松且 GPU 闲则激进预制。
**主张一句话**: KV 构建从 agent 激活的附属动作, 升格为可调度、可推迟、可共享、按容量定价的
独立活动 —— 四 baseline 各占一角, 组合无人占据。
**最小验证显存**: 当前消融 <6GB(Qwen3-1.7B bf16+2k ctx); 8路共享流 <8GB; 8B 升级 ~18GB
—— 单张 4090 全覆盖(AgentServe 亦以消费级单卡为目标)。

### E11-KV+host: 三层驻留阶梯(2026-09-23, 用户提出引入 host mem)

流入内容三层: T2 host文本(4B/tok) / **T1 host KV**(GPU预制后换出, 112KB/tok, 251GB RAM≈220万tok)
/ T0 GPU KV。T1 的提升代价仅 PCIe 回传(1.5k tok=168MB≈7ms, 待实测) vs T2 重 prefill ~0.2s => ~25x。
**关键解耦**: 预制的算力时机(GPU空闲时)与容量时机(激活前 just-in-time 回传)分离 —— 投机持有成本
从 HBM 押金降为 PCIe 带宽, P(投机划算) 大幅上移, 直接改善机制1的投机经济学。
生命周期: 流入->T2; GPU闲->预制T0; HBM紧->换出T1; 激活->T1回传(7ms)或T2 prefill;
压力->T0->T1(保算力投资)->T1->T2(弃算力保信息)。
驱逐层级(承前扩展): 预制T1(近零) > 预制T0 > 等待agent KV > 活跃agent KV。
与 InferCept/LAMPS 划界: 它们换出被阻塞agent的既有KV(止损), 这里换出投机预制的未来KV(投资)。
待实测: PCIe 换出/回传实际耗时 vs 重prefill(脚本已备, consec2 后跑)。

### E11-KV 修订(2026-09-23, 用户反馈)

**场景重设(约束)**: 单用户 + host mem 32-64GB + 单桌面级 GPU(<=5090 32GB)。
- 推论: 单用户桌面上工具等待期无其他租户补位(池补位率~0) => H1 收益最大区间, E11 适配性反而增强;
- T1 可停 KV 预算: 32G host ~140k tok, 64G ~280k tok(留半给系统);
- T1 仅对 >=8B 模型开启(实测 2.4x@1.7B 不值, 4.5x@8B 起步, pinned 下 ~16x)。

**机制1+2 合并投机模板**: KV预制(2)即投机 prefill 的 draft 阶段——
draft=空闲期预建 KV, accept=激活即用(零prefill等待), reject=丢KV留文本(损失仅已付转换算力)。
1(工地/抵押二择)是同模板在"边流边建 vs 文本滞留"上的实例。

**机制4 改名: 转换时机准入**(原"文本<->KV容量定价"表述致误解)。
不是存储置换: 文本=存储态(4B/tok,不可推理), KV=使用态(112KB/tok,注意力直接消费),
转换(prefill)迟早要付; 机制管的是何时付——GPU闲+池松=预付, 池紧=延付, 压力大=已付降级回存储态。
类比换汇时机而非换什么。定量边界: 1.7B 转换仅48ms/1.5k tok => 小模型延付近零代价, 激进预付不值。

**机制3 判决(shared_prefix_probe2.py, 1.7B, 4孩子, GPU0)**:
| 父上下文 | 基线总prefill | 共享总 | 节省 | 逐字一致 |
| 243 tok | 108ms | 144ms | -33.5% | 3/4 |
| 897 tok | 135ms | 150ms | -10.7% | 3/4 |
| 2641 tok | 333ms | 193ms | +42.0% | 4/4 |
成立但有长度门槛: 短父输出下多付的一次前向固定开销(~30ms)吃掉FLOP节省;
1.7B 交叉点 ~1-2k tok, 之后逼近理论上限 (N-1)/N=75%。
推论: 8B prefill 每tok贵~3.4x而固定开销不变 => 交叉点下移 ~500tok 内,
桌面场景(8B+工具输出1-4k tok)正好落在收益区。
不一致均为 bf16 近平局(一次vs两次前向累加序), qa 两边全对, 语义无损。
v1(shared_prefix_probe.py) 的 84% 为 warmup 污染, 以 v2 为准。

### B3 架构定稿(用户三次修正合并)与 token 级 verify 实测(2026-09-23)

该路径基线本就要走 => 失败额外代价仅 draft-token 打分(~40ms)。
白送性质: verify prefill 教师强制时顺手重建 draft token 在全量上下文下的正确 KV(与投机解码
target forward 同构, 无脏 KV); 且支持前缀部分接受(匹配到第 k 个 token 收割 k 个)。

=> 多跳 mid/late 质量失守被结构性消灭(拒绝即回退正常decode); 慢流下叶子省时小(decode尾~1%),
收益主战场=多步链下游重叠: 51%链条的下游投机输入事后证明比特级正确。

### 核心2 机制定义定稿(2026-09-23, 用户): agent 级投机解码

### B3 两步链端到端实测(chain_ablation.py, 2026-09-23)

链 = 证据流 -> 答案 -> 下游消费(结论句)。draft 答案由停线判据白送, 流尾空窗投机跑下游;

| 200 tok/s | 8.42s | 8.17s | 3.0% | 4.7% |

省时结构: ≈ 接受率 x 尾部占比(decode工作/E2E), 随流速、下游长度、链深度增长——
本实验下游仅一句结论(~1.5s), 深链/长下游时尾部占主导, 省时逼近 接受率x尾部。
**与 B2 的操作点关系**: B2 45.7%省时/-10pp质量, B3 0.8-14.5%省时/零质量损失,
是质量-时延前沿上两个点, 系统可按 SLO 选择(质量容忍->B2, 平价要求->B3)。

### 归档判决(2026-09-23, 用户): B3 提升不够, 核心2消融线封存

**判决**: B3(agent级投机解码, 质量恒=A)实测省时 0.8-14.5%, 不够, 归档。

**结构性原因(为何小)**: E2E = 流时长(主项) + 尾部decode(次项)。
任何"完成后 verify"方案由定义必须等流完 => 只能攻尾部, 上限 = 接受率 x 尾部占比;
真实 agent 流速(~50tok/s)下尾部仅占 ~2-7%。
B2(45.7%)大是因为它砍的是主项(不等流完), 但付 -10pp 质量。
=> 质量平价与砍主项在"被动接收流"的设定下互斥; 要两者兼得只剩两条路(均未验证, 随线封存):
①把停止权推给上游(让 tool/上游 agent 提前终止产出, 质量风险同 B2);
②吞吐视角用等待窗服务其他链(已封存的执行器4领域)。

**E11 消融线最终账**: 单跳 B2 42.1% 无损可行; 多跳前置判据天花板(first 37/consec2 40/answer2 45 vs A 55);
B3 结构无损但 0.8-14.5%; token级verify机制本身成立(全接受51%, 6.5x)可入机制库。
数据: out_hotpot_*.json, out_chain_b3.json, verify_prefix_probe.py, chain_ablation.py。

### 归档补充: 提升不大的定量细拆(2026-09-23)
四个乘法因子: ①可作用面=尾部占比(50tok/s 下 2.8%: 流等待占97.1%, B3 定义上碰不到,
信息论边界非工程缺陷) ②接受率 38%(答案随上下文增长不稳定, 同击穿前置判据的现象)
③开销回吞(判据 0.40s >> verify 31ms, 慢流藏进到达间隙, 快流暴露: 1000tok/s 实测7.4% vs 理论13.9%)
④基准形状最坏(下游仅一句 0.59s)。
根因=资源错配: 经典投机解码的"等待"就是负载本身(接受即砍主项);
这里等待是外部时间, GPU 投机只能并行化 GPU 侧串行工作, 无法转换外部等待。
统一定律(与 wall-p 同死因): 择时/投机收益 ∝ 可作用时段占比 x 命中率 - 开销;
wall-p 上限=duty x 单位效应, B3 上限=尾部占比 x 接受率, 均为"优化小项"陷阱;
B2 大(45.7%)因砍主项(不等流完), 付质量。
会大的形状(不推进): 长下游生成/深链/GPU间快流(天花板36%)/扇出——尾部占主导时。

### E11 线正式关闭(2026-09-23, 用户): 归档, 不再实验
补记最后一条讨论结论: 等待约束精确卡在 accept 上——提前 reject 可以(流中证据与 draft
矛盾即早杀重投, 不伤质量还提高最终接受率), 提前 accept 不行(等于赌剩余输入不变答案,
退回 B2 的统计质量风险)。质量平价 ⟺ accept ≥ 流完时刻; 省时只来自 accept 路径,
故该约束正好掐住收益。经典投机解码同规则不受损, 因其前缀由同一 GPU 进程产出(无外部等待)。
E11 全部消融结论、数据、代码已入库; 后续不再实验。

## E13: 工具语义 KV 压缩(ToolKV) + 等待窗付账(2026-09-23 新目标)

**目标(用户/goal)**: GPU0 自主推进, 消融平均>=30%提升且有创新性; 主题=tool use 的 KV 压缩(KV语义)
+ 利用工具等待延迟找并发机会。

**新颖性调研结论**: 通用KV压缩(SnapKV/H2O/KVzip/ClusterKV/EVICPRESS)无工具语义;
KV管理线(InferCept/Sutradhara/Continuum)只做放置驱逐不压缩; 文本级(MemAgent/MEM1/AgentFold)需RL训练;
DeepSeek-V4.1-Flash 是架构/训练层(CED+CSA2+FP4, 需从头预训练)。
**开放位置: 系统级+免训练+工具跨度限定+消费触发+留底兜底 的 agent KV 压缩。**

**三条核心洞见**: ①消费即冷却(压缩时机由消费事件触发, 非位置/全局统计);
②留底兜底(工具原文在客户端, 重prefill安全网, 实测48ms@1.7B/165ms@8B per 1.5k tok);
③等待付账(压缩计算藏进下次工具等待窗, 已有共驻实测: 1.7B膨胀+0.9%)。

**假设**: H1 工具跨度消费后注意力骤降, 且消费轮注意力预测答案轮需求;
H2 按消费轮注意力留 top-ρ 优于位置基线(StreamingLLM式)/随机/全局H2O(同预算);
H3 质量平价下 KV显存降>=30%(工具跨度占上下文60-90%, 预期50-80%), 定预算下并发/吞吐升>=30%;
H4 压缩计算隐藏于等待窗。

**消融臂**: A 全KV / B ToolKV(消费触发+注意力评分留ρ) / C 跨度位置基线(首尾) /
D 跨度随机 / E 全局H2O(同总预算, 语义主张的关键对照) / F ρ=0整跨度丢弃+按需重prefill。
指标: 任务质量(EM/包含), KV显存压缩比, 定KV预算下最大并发×实测批量decode吞吐。

## E14 目标执行(2026-09-24, /goal: 量化重建成本->临时KV视角->新实验超baseline 20%)

### 步骤1: 工具KV重建成本量化(rebuild_cost_probe.py, Qwen3-8B 实测)
- 重建单价 ~120-190 ms/1k tok(前缀越长越贵: 512前缀124 -> 8k前缀197; 批量近线性);
- **A3 修正性发现: pinned host-KV 回传 19GB/s, 比重建快 17-18x**(512tok: 4ms vs 69ms)
  —— 早前 pageable 时代的 4.5x 结论被修正, 温层应走 host-KV 换出而非重建;
- **A4 决定架构: 存根态前缀上重建保真度不足**(K余弦0.94/V0.86, 最低层0.86)
  => 精度保证必须全前缀重建(确定性重算=状态比特级相同);
- A5 恢复预算: 等待1s->7.2k tok, 3s->20k, 6s->40k(桌面上下文<=8k 全放得下)。

### 步骤2: 临时KV视角定稿
工具输出=某时刻的自包含信息快照+存储近零(4B/tok, 28000x便宜) => **文本是状态,
KV 是活跃计算窗内的临时产物**; 挂起层级: 活跃=GPU KV / 温=pinned host KV(19GB/s) /
冷或溢出=文本(150ms/1k重建)。骨架(~4%)常驻, 只临时化工具KV(恢复预算不变式)。

### 步骤3: 新实验(ephemeral_serve_sim.py, 全原语本卡实测标定)
负载: episode=5轮x[decode96 -> 工具等待T -> 输出512并入], ctx 600->3.6k; 8B, KV预算7.5GB。
| T̄wait | FullKV(基线,N=13) | EPH-rebuild(最优N) | EPH-swap | swap增益 |
| 2s | 1886 eps/h | 2112 (+12%) | 2373 | **+26%** |
| 5s | 1356 | 1958 (+44%) | 2375 | **+75%** |

机制: FullKV 受显存约束(等待者白占0.52GB/agent, 准入13封顶, 随等待时长线性劣化);

**精度: 构造性恒等 FullKV**(swap=同字节; rebuild=同前缀同位置确定性重算=同状态), 无需统计验证。
**目标判定: 超 baseline 20%+ 在全部等待档达成(+26%~+345%)。**

## E14 机制层判决(2026-09-24, 用户两连问触发): 降级为组件, 不作为独立创新

**公平性修正(用户问1)**: 此前 +26~345% 是对**最弱基线**(纯GPU驻留)且 offered load 不同、
host 资源不对等的数字。同配置下允许基线使用 host(= InferCept 的 swap 动作 / vLLM CPU offload),
则 host 够用时强基线与本方案路径完全重合, 增益≈0; 仅 host 耗尽的溢出窄带有差异。
**创新性判决(用户问2, 成立)**: "重建 vs 换出择优" = InferCept(ICML'24) 的 preserve/swap/
discard+recompute 最小浪费决策; 文本层 = 其 discard+recompute 动作; 我们最多是 2026 常数下
重标定(pinned 19GB/s 使 swap 普遍占优)+溢出层。**机制无新意, E14 不独立成文。**

**资产转移(价值所在)**: E14 实测常数(重建120-190ms/1k / pinned 19GB/s / 保真度边界A4 /
恢复预算不变式)与"毫秒级坍缩-恢复"能力, 转为 **E15 的仲裁货币**: InferCept 用它优化等待期
GPU 浪费(同质负载省钱), 无人把它用作**共驻异质SLO负载的让位机制**(视觉突发到来, 文本agent
坍缩让出显存, 帧预算保住后恢复)——那是 E15 的空白: 机制在那里是工具而非主张。
主线自此 = E15(端侧多模态共驻仲裁), E14 归档为其组件库。
