# E14 实验计划: 压缩即去噪 —— 毒页感知的 agent KV 压缩
2026-09-24 立项 | 前置: E13 归档(../e13/E13_ARCHIVE.md) | 状态: 待启动

## 1. 立论(E13 幸存的独有立足点)
**毒页假设**: 多轮 agent 上下文中存在"低注意力休眠 + 高实体密度 + 任务无关"的工具输出页,
保留它们不仅浪费显存, 还**主动伤害质量**(干扰实体抢答, E13 实证 6/6 错例;
删除被判无关跨度后质量超全KV: early 70%>65%)。
**攻击面**: CommitKV(2608.07855) 的生命周期规则明确保护"低->低休眠页"不驱逐 ——
恰好把毒页永久留在缓存里。SnapKV/H2O 类按注意力质量保留则恰好保住毒页里的实体名。
**主张**: KV 压缩的判定应是三态: 已完成(丢) / 休眠待用(保) / **休眠有毒(丢, 且丢了提质)**;
毒判决 = 任务相关性判决 x 实体密度 x 删除增益测试(删除后输出对齐度不降反升)。

## 3. 我们的方法(毒页感知扩展, 叠在 CommitKV 复现之上)
对"低->低 休眠"页增加毒判决三信号:
① 任务相关性: 问题条件下的跨度判决(8B 判官, E13 实测拒判63%/召回98%; 判无关精度96%)
② 实体密度: 页内命名实体 token 占比(轻量 NER 或大写/专名启发式)
③ 删除增益: 配对测量的反向使用 —— R(E;Q) 极低且删除后对 gold 对齐度不降
   (可用教师强制 logprob 变化近似, 复用 E13 verify 机制)
判定: 休眠 ∧ (无关判决 ∧ 高实体密度) -> 降级为毒页驱逐(留存根不留实体)。
预期: 在毒页密集负载(HotpotQA改造/ToolHop干扰)上, 相对 CommitKV 复现
质量 +2~5pp(去毒) 且显存额外 -10~20%(休眠页部分转毒页)。

## 4. 实验矩阵与判定
E14.1 复现关卡: CommitKV/00902-TE 在 ToolHop+FRAMES @8B 复现出论文量级(-4pp@5x / -0.5pp@0.2);
       不达标先修复现, 不进入下一步。
E14.2 毒页验证: 毒页密集负载上 CommitKV-repro vs +毒判决, 主指标=质量差与"超FullKV"点是否存在。
E14.3 消融: 三信号逐个去除; 毒判决错杀率(gold被判毒的比例, 目标<2%)。
E14.4 规模: 8B vs 14B(毒判决质量随规模)。
**止损条件**: E14.2 中毒判决相对 CommitKV-repro 提升 <1.5pp 或错杀 >5% -> 立论不成立, 归档。

## 6. 相邻方向调研(2026-09-24, 用户四问)
### 6.1 多agent KV 共享 — 拥挤, 不建议进入
KVCOMM(2510.12872 跨上下文KV通信) / TokenDance(2604.03143 master KV+块稀疏diff, 11-17x)
/ LRAgent(base+低秩adapter共享, Flash-LoRA-Attention) / DroidSpeak / KVFlow /
PolyKV(2604.24971 非对称压缩共享池) / QKVShare(2605.03884 端侧agent间量化handoff)。
### 6.2 混合精度/稀疏(按语义分级) — 已被占, 且已延伸到端侧与agent
QKVShare: token级混合精度 2-16bit CacheCard, 2.8x密度, TTFT 1030->397ms@8K;
TriAxialKV(2605.17170): 面向 agentic 任务的极低精度KV量化;
Edge Q4 持久KV(2603.04428): 每agent KV 4bit 落盘消除 re-prefill;
经典非对称K/V量化(K与V离群模式不同)已是共识。**"工具输出低比特/推理高比特"的语义分级未见专文,
但属于 TriAxialKV+CommitKV 的显然组合, 单独立论弱。**
### 6.3 先压缩后恢复 — 已成子领域(与我们T2/T1/T0阶梯同源)
RestoreKV(2608.01247): 驱逐前生成"上下文条件补全"以保住行为(不是选更好子集, 而是造补丁);
PatchKV(2609.26219): 上下文被编辑后的前缀/更新段/对齐后缀分解恢复;
CacheFlow(2604.25080): 3D并行KV恢复; CacheTTL: 工具期驱逐后 recompute-vs-reload 决策;
Edge Q4: 量化落盘即"压缩-恢复"。**我们的文本留底重建属同族, 无新意; 但"恢复的是毒页则不该恢复"
与 RestoreKV 的补全思路正交, 可作为 E14 的附加消融。**
### 6.4 端侧多模态agent争抢GPU — **相对空白, 唯一可立项的相邻方向**
已有: Nova(2509.21301 实时 agentic VLM serving, 跨阶段自适应并行) 明确指出
**视觉编码器推理与LLM decode预分配KV争抢显存 -> 缓存驱逐/重算**, 其解法是视觉编码器权重异步换出;
Mosaic(2605.18710 训练侧空间复用); EdgeCoInfer/移动SoC刻画(2501.14794, NPU/GPU/DLA异构调度);
VL-Cache/MEDA/FastCache(模态感知KV压缩, 单模型内部)。
**空白: 多个不同模态 agent(视觉/视频/图形渲染/文本)在同一端侧GPU上并发时的
"跨agent跨模态资源仲裁" —— 现有工作要么单模型内部(VL-Cache), 要么单agent流水(Nova),
要么训练侧(Mosaic)。与本仓 MPK/greenctx/POD 共驻复现资产直接可接。**
候选立项 E15(待定): 端侧多模态 agent 共驻仲裁 —— 模态决定资源画像(视觉编码=计算密集突发,
LLM decode=访存密集持续, 渲染=固定帧预算硬实时), KV/显存/SM 三资源联合分配,
可复用 E13 毒页判决做跨模态上下文降级。

## 7. 方向 B(用户提案, 2026-09-24; 框架于 09-24 二次修订) —— **E14 主线**
### 7.0 框架修订: 从'压缩+文本兜底'(补丁) 到 'KV 临时化'(换代)
用户质疑'文本兜底更像补丁'成立: 给有损压缩加安全网只是机制改良。强框架:
**文本是状态, KV 只是活跃计算窗内的临时产物**。依据: 8B 重建 110ms/1k tok(实测),
工具等待 1-6s => 单次等待可重建 9k-55k token, 即'一个 agent 的上下文能在它自己的等待窗里重建完'。
推论(与现有全部工作的前提相反: 它们都视 KV 为需长期管理的持久物):
① 空闲 agent 的 GPU 占用 ~= 0 => 并发上限从**显存约束**变为**活跃计算约束**
   (8B/24GB 实算: 4096预算下仅 ~13 agent 常驻; 临时化后空闲 agent 近零, 量级 10-50x);
② 质量-轮数曲线由衰减变**平**(有损压缩随轮数单调掉点, 临时化只影响时延);
③ 剩余问题是真问题: 重建带宽/预重建时机/活跃集准入 = 调度(与 E15 接口), 非工程补丁。
**指标随之改变**: 主指标 = 每GB可托管并发 agent 数 + 质量随轮数的衰减斜率,
而非'固定预算下掉几 pp'。
### 7.0b 适用边界(用户约束, 决定性): 只临时化 tool-use KV
**恢复预算不变式: 需重建 token 数 x 每token prefill 成本 <= 工具等待窗。**
等待窗不随上下文增长, 重建成本随上下文线性/超线性增长 => 全量临时化必在某长度崩溃
(KV 重建比工具本身还慢)。故必须分层:
| 层 | 内容 | 占比(E13实测) | 策略 |
| 骨架常驻 | 系统提示/工具定义/用户问题/**agent自身推理链** | ~4% | 永不临时化(薄、复用最高、是重建其他部分的上下文前提) |
| 工具输出 | log/grep/检索观察 | **96%** | 存根+文本主存, 按需重建 |
该划分免费: 工具输出既最胖又信息密度最低, 只临时化它即拿到几乎全部收益。
**真正绑定条件是工作集而非上下文长度**: 每轮缺页跨度数 x 跨度长度 <= 等待窗预算。
E13 实测每问题 gold 跨度 2/10; SWE-bench 类每步只回看少数文件 => 工作集有界则历史可无界。
长程算例: 10万tok/500跨度, 每轮缺页2-5跨度=400-1000tok=45-110ms, 任何等待窗均可容纳。
**失败模式=抖动(thrashing)**: 需横扫大量跨度的轮次(总结全部/对比所有候选)工作集->全量,
重建>11s 超窗。必测: 缺页率随任务类型的分布曲线 + 越界逃生策略
(该 agent 降级常驻 / 停止进一步临时化 / 整段预重建)。
### 7.1 经济学(已实测)
文本 4B/token vs KV 112KB/token = 28000x; 桌面 32-64GB host 存文本 ~千万 token(存KV仅~280k) =>
**文本备份在容量上无限, 代价是恢复须重算**(实测重prefill 1.5k tok: 1.7B 48ms / 8B 165ms)。
### 7.2 相对已有工作的两个未利用后果(立论核心)
① **可恢复性解放了压缩保守度**: CommitKV 因错误永久损质而必须保护"低->低休眠页";
   有文本兜底后判错仅=多付一次重建延迟, 故可压得更狠、让恢复兜错。**质量上限=FullKV**, 契合"跑分优先"。
② **恢复触发不必依赖模型自检索**: E13 J臂死于"让模型用文本点名"(1.7B 56/60固定点名, 8B召回67%);
   改用**存根注意力作为缺页信号**: 每跨度在KV留8-token存根(段号+标题+首句),
   答案生成时注意力大量压向某存根 => 触发该跨度重算换入。
   与 Quest/InfLLM 的区别: 它们在"已存在的KV页"间选(受容量约束), 存根是8token语义指针, 原文在host近零成本。
### 7.3 占位核查(2026-09-24)
已被占: 空闲期预热(CACHESCOUT) / 预测式预取+驱逐(PBKV 2605.06472) / 三级放置(生产实践) /
传输vs重算成本模型 / 局部重算窗口(PatchKV, 13-21x)。
**未见**: 文本为主存 + 存根注意力缺页 + 可恢复性驱动的激进压缩 这一组合。
### 7.4 实验设计(跑分优先)
臂: A FullKV / B CommitKV复现 / **C 存根+注意力缺页(本方案)** / C-oracle(gold跨度必恢复, 上界)
/ C-ondemand(仅关键路径恢复) vs C-prefetch(等待窗预取恢复) / D E13-H(单向压缩对照)。
主指标: **每GB并发agent数** + **质量随轮数衰减斜率** + 准确率(目标 >= FullKV -1pp) / 轮间峰值KV / 恢复触发次数与命中率(触发跨度∩gold)
/ E2E 时延(含重算, 区分等待窗内外) / 定预算吞吐。
关键待定参数(需扫描): 存根长度(4/8/16 tok)、缺页阈值(存根注意力占比)、
恢复粒度(整跨度 vs 半跨度)、预取时机(工具发起时/返回前/答案首token前)。
风险: 位置编码——恢复的跨度须按原始位置重插(E13 手术件已验证显式 position 续推可行);
KV 碎片与 cache_position 连续性在 vLLM 页式后端的落地需另评估(本阶段用 transformers 验证机制)。

### 7.5 新增关键实验(框架修订后)
E14.B1 **并发密度**: 固定 24GB/8B, 测"可托管并发 agent 数"—— CommitKV类(4096预算常驻) vs
  临时化(空闲近零, 活跃集受重建带宽限)。指标: 稳态并发数、唤醒时延 P50/P99。
E14.B2 **质量-轮数曲线**: 多轮 agent 轨迹(ToolHop/SWE类), 画质量 vs 轮数;
  预期有损压缩单调衰减, 临时化持平。**这是"换代"主张的核心证据。**
E14.B3 **工作集刻画与抖动边界**: 每轮缺页跨度数分布 x 任务类型; 标出越过等待窗预算的比例;
  验证逃生策略把抖动轮次的时延惩罚压住。
E14.B4 骨架/工具分层消融: 全量临时化(含推理链) vs 仅工具输出临时化 —— 验证 §7.0b 的必要性。
